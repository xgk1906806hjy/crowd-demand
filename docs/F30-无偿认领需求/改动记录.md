## 详细记录

### v0.1 — 2026-11-23 — 新建

- 背景：用户指出平台应是"每个人都能发需求"，而非只有众筹一条路。PRD v0.2 定下三模式，其中无偿认领是零资金分支，与 F28 共用"发布即开放方案征集"的骨架。
- 改动内容：
  - `NeedMode` 新增 `OPEN`，`Need` 通过 `mode` 区分；无偿需求 `bountyAmount = 0`，不建托管。
  - 状态机允许 `DRAFT → BIDDING`，禁止非众筹进入 `COLLECTING` / `PLEDGING`。
  - 提案报价上限按模式取：`OPEN` 固定 0，>0 直接拒绝。
  - `voteForProposal`、`pledge` 对非众筹一律拒绝。
  - 结算 `settleProjectInTx` 对 `OPEN` 早返回，不产生放款或退款流水。
  - 前端：发布页「无偿求助」卡片、详情页无偿数据区、隐藏报价输入、需求方「关闭需求」按钮。
- 影响范围：需求发布、详情、提案、结算；众筹与悬赏路径不受影响。
- 验证方式：单元测试 153 例（含无偿零报价与超额拒绝）；`npx tsc --noEmit` exit 0；生产构建 31 路由；`deploy/smoke-f28.sh` 在服务器验证"无偿发布 + 零报价提案"通过。
- 遗留：零金额项目的里程碑计划无法拆分，见 `功能详细说明.md` 第 7 节。

### v0.2 — 2026-11-24 — 需求变更

- 背景：用户要求每个人都可以领取需求，不再限制开发者角色。
- 改动内容：无偿需求（`OPEN`）的领取方不要求开发者角色、不要求实名，任何登录用户可在竞标期提交零报价方案；与 F12 同步生效（无独立代码改动）。
- 影响范围：无偿需求详情页方案表单展示条件。
- 验证方式：`proposal-service.test.ts` 新增 OPEN 未实名提交用例通过。
