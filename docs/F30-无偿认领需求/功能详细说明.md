# F30 — 无偿认领需求

> 功能编号来源：`docs/开发方案.md` 2.1 节（PRD v0.2 第 5.1 节）。
> 本文件是该功能的唯一需求与实现说明；改动必须同步追加到 `改动记录.md`。

## 1. 目标

让"有人需要、但没人愿意为此付钱"的需求也能发出来：需求方免费发布，愿意帮忙的开发者自愿接单，平台不涉及任何资金流转。

这是"每个人都能发需求"的兜底形态——不实名也能看，但要发需求仍需实名（沿用 F04 的合规闸门）。领取方（提交方案的人）不要求实名、也不要求开发者角色（2026-11-24 起），任何登录用户都可自愿接单。

## 2. 用户故事

- 作为需求方：我想发一条小工具需求，不打算付钱，但希望有人刚好愿意做。
- 作为开发者：我想找一些轻量、可攒信誉的小活，不图报酬。
- 作为平台：无偿需求不产生资金，不能给用户造成"有人付钱"的错觉。

## 3. 需求细则

| 项 | 规则 |
| --- | --- |
| 发布入口 | `/console/needs/new` 选「无偿求助」模式 |
| 必填 | 标题、痛点描述（≥30 字） |
| 金额 | 不填，`targetAmount` 与 `bountyAmount` 均为 0；不创建 `BountyEscrow`、不调支付网关 |
| 征集期 | `bountyDays` 1–60 天，落到 `Need.bountyDeadline` |
| 初始状态 | 发布即 `BIDDING`（跳过 `COLLECTING` / `PLEDGING`） |
| 提案 | 必须零报价（`quote = 0`），报价 >0 直接拒绝；不校验承诺总额 |
| 投票 | 不支持。众筹的承诺票权在无偿模式下无意义，`voteForProposal` 对非众筹返回 403 |
| 选标 | 需求方本人在提案列表里选定一个，无票数参考 |
| 资金 | 全链路无资金：无托管、无放款、无退款 |
| 撤回 | 需求方在 `BIDDING` 可「关闭需求」，走 `bounty-cancel` 接口，状态转 `REFUNDED`（无钱可退，仅置状态） |

## 4. 状态流转

```
DRAFT ──发布──> BIDDING ──选定方案──> IN_PROGRESS ──交付验收──> ACCEPTING? ──> COMPLETED
   └────────────撤回────────────> REFUNDED
```

- 允许 `DRAFT → BIDDING`，禁止 `DRAFT → COLLECTING`（众筹专属）。
- 无偿项目 `Project.totalAmount = 0`，结算时直接结项，不产生放款流水。

## 5. 技术实现

- 模式枚举：`NeedMode.OPEN`（`prisma/schema.prisma`）。
- 状态机：`src/domain/need/state-machine.ts` 的 `canTransitionForMode` 按 mode 放行/拒绝。
- 提案报价：`src/domain/proposal/service.ts` 的 `create` 按模式取上限，`OPEN` 固定 0。
- 结算：`src/domain/payout/service.ts` 的 `settleProjectInTx` 对 `OPEN` 早返回，不做资金分配。
- 前端：发布页模式卡片、详情页「无偿」数据区（费用=无偿 / 资金状态=不涉及资金）、`ProposalForm` 隐藏报价输入。

## 6. 验收标准

- [x] 无偿需求发布后状态为 `BIDDING`，不产生 `BountyEscrow` 记录
- [x] 开发者提交 0 元报价成功，>0 元被拒绝（400）
- [x] 无偿模式下支持者投票返回 403
- [x] 需求方可关闭需求，状态转 `REFUNDED`
- [x] 全链路不产生任何账本流水
- [ ] 零金额项目仍能创建里程碑计划并逐节点验收（当前金额校验会拦住，待补）
- [ ] Playwright E2E 覆盖无偿发布到结项

## 7. 已知限制

1. `MilestonePlanForm` 要求各节点金额合计等于项目总额，无偿项目总额为 0 时无法拆分节点。需要补"零金额节点"分支：允许金额全 0、仅按顺序验收。
2. 无偿需求没有报酬约束，容易被低质方案占位，后续可加"每天接单上限"或信誉门槛（F03 联动）。
3. 无偿需求结项不产生放款，`Payout` 表无记录，收益统计类报表需显式排除。
