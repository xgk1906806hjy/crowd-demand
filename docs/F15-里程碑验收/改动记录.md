## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：PRD 5.5 要求「付费用户确认」后放款，避免开发者单方面宣布完成。
- 改动内容：
  - `MilestoneService.accept()`：发起者/运营方验收 → 节点 ACCEPTED → 同事务放款（F16）→ 全部释放则结算（F17）。
  - `MilestoneService.reject()`：驳回需 ≥5 字原因，节点转 DISPUTED，写审计。
  - API：`POST /api/milestones/[id]/accept`、`POST /api/milestones/[id]/reject`。
  - UI：`MilestoneActions` 的验收模式（通过需二次确认、驳回内联填写原因）。
- 影响范围：
  - 验收与放款不可分离，杜绝「验收了没付钱」。
  - MVP 验收人 = 需求发起者（代表付费方），多支持者投票验收留待后续。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：111 用例全绿（越权、未提交、驳回校验）
  - `npm run build`：EXIT=0（最终全量构建 41 条路由全部生成）

### v0.2 — 2026-11-23 — Bug 修复

- 背景：任意 `SUBMITTED` 节点都能先验收放款，顺序只靠界面约定；且验收无并发认领，同一节点可能被重复处理。
- 改动内容：
  - 前置节点未 `RELEASED` 时返回 `INVALID_STATE`（「请先完成前置里程碑」）。
  - 用 `updateMany({ id, status: SUBMITTED })` 原子认领为 `ACCEPTED`，并发只有一方成功（另一方 CONFLICT）。
  - 外部网关调用失败/记账失败时回滚认领为 `SUBMITTED`，并返回 503；同 reference 重试不会二次出款。
- 验证方式：新增 3 例（跳级拒绝、通道失败回滚、托管余额不足回滚）；`npx vitest run` 里程碑 14 例全绿。
