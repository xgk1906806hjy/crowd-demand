## 1. 功能目标

由付费方（需求发起者）逐节点确认交付物是否达标：通过则触发放款，不通过则退回开发者修改，避免开发者自说自话。

## 2. 用户故事

- 作为发起者，我想验收节点并决定是否放款，以便保证交付质量。
- 作为开发者，我想知道节点被驳回的原因，以便修改后重新提交。
- 边界场景：
  1. 节点还没提交就点验收 → 拒绝。
  2. 非发起者点验收 → 拒绝。
  3. 驳回不写原因 → 拒绝（至少 5 字）。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| milestoneId | path | 是 | 存在且状态 SUBMITTED |
| reason | string | 驳回时必填 | ≥5 字 |

### 3.2 输出

- 通过：`{ released, projectCompleted, refunded }`
- 驳回：`{ status: DISPUTED }`

### 3.3 业务规则

1. **验收人**：需求发起者或运营方（MVP 以发起者为付费方代表）。
2. **状态限制**：仅 `SUBMITTED` 可验收/驳回。
3. **通过与放款同一事务**：验收动作即触发 F16 放款，避免「验收了但没付钱」。
4. **驳回**：节点转 `DISPUTED`，开发者需重新提交（后续可扩展为重新打开 PENDING）。
5. **审计**：通过写 PAYOUT，驳回写 MILESTONE（含原因）。

### 3.4 状态流转

```
SUBMITTED ──验收通过──→ ACCEPTED ──放款──→ RELEASED
SUBMITTED ──驳回──→ DISPUTED
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 需求发起者 | 验收通过、驳回 |
| 中标开发者 | 查看结果、重新提交 |
| 运营方 | 可代为验收 |

## 4. 技术实现

- 涉及模块：`src/domain/milestone/service.ts`（`accept`、`reject`）、`src/app/api/milestones/[id]/accept|reject/route.ts`、`src/components/need/milestone-actions.tsx`
- 事务：验收状态 + 放款 + 可能的结算在同一事务
- 资金：通过即放款（F16），全部通过即结算（F17）

## 5. 验收标准

- [x] 核心流程可用：通过即放款、驳回可改
- [x] 异常场景有明确提示：未提交、越权、原因过短
- [x] 单元测试通过：`tests/unit/milestone-service.test.ts`（越权与未提交用例）
- [x] 驳回原因写入审计日志
- [ ] 多支持者投票验收（PRD 提及「付费用户确认」，MVP 由发起者代表）

## 6. 测试要点

1. 未提交节点验收返回 INVALID_STATE。
2. 非发起者验收返回 FORBIDDEN。
3. 通过后节点 RELEASED、放款成功。
4. 驳回原因 <5 字被拒绝。
