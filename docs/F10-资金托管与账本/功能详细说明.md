## 1. 功能目标

用复式账本记录每一分钱的流向，让「谁的钱、什么时候、因为什么、从哪个账户到哪个账户、余额变成多少」全部可追溯、可对账，杜绝直接改余额导致的资金黑洞。

## 2. 用户故事

- 作为支持者，我想知道我的订金现在在托管账户里，以便放心。
- 作为运营方，我想核对平台托管总额与每笔业务流水，以便对账。
- 边界场景：
  1. 同一笔业务被重复提交 → 账本唯一键拦截，不产生重复分录。
  2. 金额出现浮点 → 类型层面即不可能（bigint）。
  3. 记账金额为 0 或负数 → 直接抛错，不写库。

## 3. 详细需求

### 3.1 输入

记账函数 `postTransfer(tx, input)`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| from | AccountRef | 是 | 出账账户 |
| to | AccountRef | 是 | 入账账户 |
| amount | bigint | 是 | 分，必须 > 0 |
| bizType | PLEDGE/RELEASE/REFUND | 是 | 业务类型 |
| bizId | string | 是 | 业务单号 |
| idempotencyKey | string | 是 | 派生 `:out` / `:in` |
| pledgeId | string | 否 | 关联承诺 |
| memo | string | 否 | 备注 |

### 3.2 输出

两条 `LedgerEntry`：出账 DEBIT（`balanceAfter = 原余额 - amount`）、入账 CREDIT（`balanceAfter = 原余额 + amount`）。

### 3.3 业务规则

1. **一借一贷**：每笔业务必须成对写入，金额相等、方向相反。
2. **账户视角**：DEBIT = 流出，CREDIT = 流入；余额 = ΣCREDIT − ΣDEBIT。
3. **三类虚拟账户**：支持者 `BACKER`、平台托管 `ESCROW`、开发者 `BUILDER`。
4. **禁止裸改余额**：任何资金变动只能通过 `postTransfer`，余额由流水推导。
5. **不可删除**：账本流水分录只增不改（数据库层不提供删除入口）。
6. **幂等**：`idempotencyKey` 唯一，重复记账直接失败而非叠加。
7. **金额整数分**：类型为 bigint，接口层输出字符串。
8. **事务级串行锁**：每笔记账先取 `pg_advisory_xact_lock`（事务提交/回滚自动释放），把「读余额 → 写余额快照」串行化，防止并发事务互相覆盖 `balanceAfter`。
9. **托管不可透支**：从 `ESCROW` 出账时校验余额 ≥ 金额，不足直接抛「托管账户余额不足」，防止并发超额放款。

### 3.4 状态流转

无独立状态；资金流向随业务：

```
承诺  BACKER  --DEBIT-->  ESCROW  --CREDIT
退款  ESCROW  --DEBIT-->  BACKER  --CREDIT
放款  ESCROW  --DEBIT-->  BUILDER --CREDIT
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 普通用户 | 无直接记账权限（只能通过业务动作触发） |
| 领域服务 | 在事务内调用 `postTransfer` |
| 运营方 | 查看流水（F19） |

## 4. 技术实现

- 涉及模块：`src/domain/ledger/service.ts`（`postTransfer`、`balanceOf`、`lockLedger`、账户工厂）、`src/infrastructure/payment/gateway.ts`
- 数据库：`LedgerEntry`（accountType/accountId/direction/amount/balanceAfter/bizType/bizId/idempotencyKey）
- 事务：必须在 `prisma.$transaction` 内调用
- 并发：`lockLedger()` 用 `pg_advisory_xact_lock` 对托管账户串行化；出账前校验托管余额
- 余额计算：当前实现为读取该账户全部流水累加（MVP 数据量小）；数据量上来后改为聚合查询或账户余额表 + 快照
- 外部依赖：托管账户由持牌机构提供，平台只维护虚拟账

## 5. 验收标准

- [x] 托管余额不足时拒绝划出，余额恰好够时放款后归零
- [x] 事务级串行锁接入（`lockLedger`）
- [ ] 与持牌机构对账文件联调（生产接入阶段）

## 6. 测试要点

1. 一笔承诺生成 2 条分录，方向与余额快照正确。
2. 借贷总额恒等。
3. 多次承诺后余额累加正确。
4. 退款冲销后托管余额归零。
5. 零/负金额拒绝。
6. 幂等键后缀 `:out` / `:in`。
7. 托管余额不足时 `postTransfer` 抛错，不写分录。
8. 托管余额恰好等于放款额时允许划出，余额归零。
