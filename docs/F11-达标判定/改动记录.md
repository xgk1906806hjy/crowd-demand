## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：PRD 5.3 要求「截止时间到期或提前达标 → 解锁开发阶段」「未达标全额原路退回」。
- 改动内容：
  - `PledgeService.pledge()` 内嵌达标判定：`pledgedAmount ≥ targetAmount` 时条件更新 `PLEDGING→BIDDING`，同事务锁定全部 `FROZEN` 承诺为 `LOCKED`，写状态日志。
  - 新增 `src/domain/pledge/lifecycle.ts`：
    - `refundNeedPledges(needId)`：逐笔 `ESCROW → BACKER` 冲销，幂等键 `refund:{pledgeId}`，写 `PaymentOrder(REFUND)`。
    - `expireOverdueNeeds(now)`：扫描过期需求 → 流拍 `FAILED` → 退款 → `REFUNDED`，返回汇总。
  - 新增 `POST /api/admin/needs/expire`（仅 OPERATOR）。
- 影响范围：
  - 达标后需求不再接受新承诺（状态已离开 PLEDGING）。
  - 已达标但到期的需求不会被流拍。
  - 退款为全额、原路、逐笔，不收取任何手续费。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：89 用例全绿（达标 1 例 + 生命周期 4 例）
  - `npm run build`：EXIT=0，26 条路由全部生成（含 6 个新 API 与 1 个新页面）

### v0.2 — 2026-11-23 — Bug 修复

- 背景：三处缺口——① 状态机允许 `BIDDING → FAILED` 但无退款路径，托管资金会滞留；② 外部退款失败仍被置 REFUNDED；③ 到期结算只能人工触发。
- 改动内容：
  - 新增 `failNeedAndRefund()`：仅征集/承诺/竞标可走；`FAILED → 退款 → REFUNDED`，可重入，退款未全部成功时保持 `FAILED` 并返回 503。
  - `refundNeedPledges` 改为逐笔 try/catch，失败的笔数计入 `failed`，不阻塞其余支持者；PaymentOrder 记录真实 provider 与回执号。
  - `expireOverdueNeeds` 复用 `failNeedAndRefund`，汇总新增 `failedNeeds`。
  - 新增 `POST /api/internal/cron`（校验 `x-cron-secret`）；`docker-compose.prod.yml` 增加 cron 容器每 5 分钟调用；`CRON_SECRET` 未配置时接口拒绝。
  - `src/instrumentation.ts` 启动时调用 `assertProductionPaymentSafe()`。
- 验证方式：生命周期测试增至 7 例（竞标终止、开发中拒绝、通道失败保持 FAILED）；`npx vitest run` 125 例全绿。
