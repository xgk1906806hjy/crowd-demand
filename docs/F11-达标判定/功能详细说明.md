## 1. 功能目标

回答两个决定项目生死的问题：**钱够了没有？时间到了怎么办？** 达标则锁定资金进入竞标，未达标则自动流拍并把钱一分不少退回去。

## 2. 用户故事

- 作为支持者，我想在需求未达标时自动拿回订金，以便不用担心钱被卡住。
- 作为运营方，我想一键触发到期结算，以便处理积压的过期需求。
- 边界场景：
  1. 最后一笔承诺刚好补齐目标 → 立即转 BIDDING，不再接受新承诺。
  2. 并发两笔承诺同时补齐 → 只有一次流转成功，不重复写日志。
  3. 已达标但时间到期 → 不流拍，继续走竞标。

## 3. 详细需求

### 3.1 输入

| 场景 | 触发方式 | 参数 |
| --- | --- | --- |
| 承诺达标 | F09 承诺成功后自动判定 | 无 |
| 到期结算 | `POST /api/internal/cron`（部署侧 cron 容器，每 5 分钟）或 `POST /api/admin/needs/expire`（运营兜底） | now（默认当前时间） |

### 3.2 输出

- 达标：需求 `PLEDGING → BIDDING`，全部 `FROZEN` 承诺 → `LOCKED`。
- 到期未达标：`COLLECTING/PLEDGING → FAILED`，退款完成后 `FAILED → REFUNDED`。
- 结算汇总 `{ expiredNeeds, refundedPledges, refundedAmount }`。

### 3.3 业务规则

1. **达标条件**：`pledgedAmount ≥ targetAmount` 且 `targetAmount > 0`。
2. **原子流转**：用 `updateMany({ where: { id, status: PLEDGING } })` 条件更新，保证只流转一次。
3. **锁定资金**：达标时同事务把该需求全部 `FROZEN` 承诺改为 `LOCKED`。
4. **到期处理范围**：仅 `COLLECTING` / `PLEDGING` 且 `deadline < now`。
5. **已达标不流拍**：承诺期已达标的需求即使到期也继续进入竞标。
6. **全额退款**：逐笔从托管退回支持者，幂等键 `refund:{pledgeId}`。
7. **两段状态日志**：流拍记 `→FAILED`，退款完成记 `FAILED→REFUNDED`。
8. **审计**：结算写 `AuditLog`（REFUND / ADMIN）。
9. **竞标中终止也退款**：运营方把 `BIDDING` 需求流转为 `FAILED` 时走同一套 `failNeedAndRefund`，避免「已置流拍、托管资金留在账上」。
10. **退款未完成不置终态**：任一笔外部退款失败时需求停在 `FAILED`，承诺保持 `FROZEN/LOCKED`，可再次调用补齐，避免「标记已退款但钱没回来」。
11. **可重入**：需求已在 `FAILED` 时再次执行只补退剩余承诺，不重复划账（幂等键 `refund:{pledgeId}`）。

### 3.4 状态流转

```
PLEDGING ──承诺 ≥ 目标──→ BIDDING
COLLECTING/PLEDGING ──到期未达标──→ FAILED ──退款完成──→ REFUNDED
PLEDGING（已达标） ──到期──→ 保持 PLEDGING/BIDDING，不流拍
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 支持者 | 无（系统自动） |
| 发起者 | 无 |
| 运营方 | 手动触发到期结算 |
| 系统 | 承诺达标自动判定、定时到期结算 |

## 4. 技术实现

- 涉及模块：`src/domain/pledge/service.ts`（达标判定内嵌于承诺事务）、`src/domain/pledge/lifecycle.ts`（`refundNeedPledges`、`failNeedAndRefund`、`expireOverdueNeeds`）、`src/app/api/internal/cron/route.ts`、`src/app/api/admin/needs/expire/route.ts`
- 数据库：`Need.status`、`NeedStatusLog`、`Pledge.status`、`LedgerEntry`、`PaymentOrder`
- 事务边界：单笔退款一个事务；状态流转与日志走 `transitionNeedInTx`
- 定时任务：`POST /api/internal/cron` 校验 `x-cron-secret`，由 `docker-compose.prod.yml` 中的 cron 服务每 5 分钟调用；未配置 `CRON_SECRET` 时接口直接拒绝
- ⚠️ 生产注意：外部退款先于记账调用，网关必须按 reference 幂等；接持牌机构后如需对账文件，再补 outbox/reconciliation

## 6. 测试要点

1. 达标后状态、承诺锁定、日志三者一致。
2. 并发达标只流转一次（条件更新）。
3. 到期未达标：两段日志、全额退款、终态 REFUNDED。
4. 已达标到期不流拍。
5. 未到期不处理。
6. 退款金额汇总等于承诺总额。
7. 竞标中被终止：两段日志、承诺全部 REFUNDED、托管余额归零。
8. 外部退款失败：需求停在 FAILED、承诺未置 REFUNDED，重试可补齐。
9. 开发中需求不能直接流拍退款（返回 INVALID_STATE）。
