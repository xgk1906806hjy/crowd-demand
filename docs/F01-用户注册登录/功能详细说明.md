## 1. 功能目标

用手机号验证码实现"注册即登录"，为全平台提供统一身份。这是所有资金操作的前置（F02 实名、F09 承诺都依赖本功能），因此必须做到：会话安全、验证码防暴力破解、登录态可被接口层统一读取。

## 2. 用户故事

- 作为访客，我想要输入手机号并收到验证码完成登录，以便无需记忆密码就能使用平台。
- 作为新用户，我首次验证码登录时自动完成注册，以便降低使用门槛。
- 作为已登录用户，我希望会话在有效期内保持，过期后能重新登录。
- 边界场景：
  - 验证码输错次数过多 → 限制并提示，防止暴力破解。
  - 验证码过期或被重复使用 → 拒绝并提示重新获取。
  - 短时间内频繁请求验证码 → 限流。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| phone | string | 是 | 中国大陆手机号 `^1[3-9]\d{9}$` |
| code | string | 是（登录校验时） | 6 位数字 |
| purpose | enum | 是 | `LOGIN`（本功能只用 LOGIN） |

### 3.2 输出

- 发送验证码：返回 `{ sent: true, expiresIn: 300 }`（mock 环境额外在服务端日志打印验证码）。
- 校验登录：返回 `{ token, user: { id, phone, nickname, roles, kycStatus } }`，token 为 JWT，放进 HttpOnly Cookie。
- 当前用户：返回当前会话用户信息。

### 3.3 业务规则

1. 手机号是唯一身份标识；首次登录自动创建 User，默认角色 `[BACKER]`、`kycStatus=NONE`、`reputationScore=0`。
2. 验证码 6 位，有效期 5 分钟，哈希存储（禁止明文），一次性使用（消费后 `consumedAt` 置位）。
3. 单个验证码最多校验 5 次，超过作废；同一手机号 60 秒内只能请求一次验证码。
4. 登录成功签发 JWT（含 userId、roles），有效期 7 天，通过 `HttpOnly + SameSite=Lax` Cookie 下发；生产环境加 `Secure`。
5. 会话密钥取 `AUTH_SECRET`，禁止硬编码。
6. 所有认证事件写审计日志（`AuditAction.AUTH`）。

### 3.4 状态流转

不涉及业务状态机（会话为无状态 JWT）。验证码生命周期：

```
未消费 → 已消费（校验成功）
未消费 → 已过期（超过 5 分钟）
未消费 → 已作废（尝试次数超限 / 被新验证码替代）
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 访客 | 请求验证码、校验登录 |
| 已登录用户 | 查看当前用户信息、退出登录 |
| 运营方 | 无特殊权限（本功能） |

## 4. 技术实现

- 涉及模块：
  - `src/domain/auth/` —— AuthService（业务逻辑：验证码校验、注册/登录、签发会话）
  - `src/infrastructure/sms/gateway.ts` —— 短信适配器接口 + Mock 实现
  - `src/lib/session.ts` —— JWT 签发/校验（jose）
  - `src/app/api/auth/*` —— Route Handlers（send-code / verify / me / logout）
  - `src/lib/auth.ts` —— `getSession`（JWT 身份）+ `getSessionUser`（回源数据库读最新 roles/kycStatus）
  - `src/app/(public)/login/` —— 登录页
  - `src/middleware.ts` —— 受保护路由的会话校验
- 数据库变更：`User`、`VerificationCode`、`AuditLog`（在初始 schema 中已建立）。
- 外部依赖：短信走 `SmsGateway` 适配器，MVP 用 Mock。
- 资金操作：无。

## 6. 测试要点

- 手机号格式校验（合法/非法）。
- 验证码：正确 / 错误 / 过期 / 已消费 / 尝试超限。
- 同一手机号 60 秒内重复请求被限流。
- 首次登录创建 User，二次登录复用同一 User（phone 唯一）。
- JWT 可被正确校验，篡改后校验失败。
- 审计日志在关键节点产生记录。
