### v0.3 — 2026-11-23 — Bug 修复

- 背景：JWT 中的 `roles` 是登录时快照，运营授权/角色申请后不重新登录不生效；后台接口与页面均按快照判权。
- 改动内容：
  - `src/lib/auth.ts` 新增 `getSessionUser()`：JWT 只作为身份凭证，roles/kycStatus 回源 `prisma.user`；新增 `isOperator()`。
  - `src/app/admin/layout.tsx` 与 4 个后台接口（ledger / reports / reports handle / needs expire）改用 `getSessionUser()`。
  - 功能说明修正「集成测试通过」的错误表述（当前只有内存单测）。
- 影响范围：角色变更即时生效；JWT 仍只承载 userId 与签发时间。
- 验证方式：`npx tsc --noEmit` 0 错误；`npx vitest run` 125 例全绿。

### v0.4 — 2026-11-23 — 合规闸门重构（部署后修复）

- 背景：`MockSmsGateway` / `MockKycGateway` 在 `NODE_ENV=production` 下无条件抛错，导致生产构建的演示实例**根本无法登录**（注册第一步就 500）。而 `assertProductionPaymentSafe()` 只在启动钩子里判一次，规则散落在三处、判分不一致。
- 改动内容：
  - `src/lib/env.ts` 新增统一闸门 `assertMockAdapterAllowed(kind)`：`NODE_ENV=production` 时默认抛「合规红线」；仅当显式 `APP_ENV=demo` 放行，并**每个适配器只告警一次**。`assertProductionPaymentSafe()` 改为复用该闸门。
  - 新增 `APP_ENV` 环境变量（`production` 默认 / `demo`），compose 透传；`deploy.sh` 在部署前拦截「`PAYMENT_ADAPTER=mock` 且非 demo」的组合，避免容器崩溃循环。
  - `src/instrumentation.ts` 的运行时判断由 `!== "nodejs"` 改为 `=== "edge"`：standalone 下 `NEXT_RUNTIME` 可能为空，旧写法会静默跳过合规校验。
  - `createPaymentGateway()` 内再加一道同规则校验（真正动钱前拦截），防止自定义入口绕过启动钩子。
  - 新增 `tests/unit/compliance-gate.test.ts`（4 例）锁死该规则。
- 影响范围：登录/实名在演示实例恢复可用；正式环境仍需接入真实服务商，否则启动即失败。
- 验证方式：`npx vitest run` 129 例全绿；部署环境冒烟脚本三个账号均能收码、登录、实名。
