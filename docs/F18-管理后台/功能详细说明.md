## 1. 功能目标

给运营方一个集中的后台：看清平台当前状态，对需求执行状态机允许的强制流转，代为处理提案选标与里程碑验收，保证异常项目能被人为推进而不卡死。

## 2. 用户故事

- 作为运营方，我想看到各状态需求数量与托管余额，以便掌握平台健康度。
- 作为运营方，我想强制推进某个卡住的需求状态，以便处理异常。
- 边界场景：
  1. 非运营方访问 `/admin` → 跳转控制台。
  2. 运营方执行非法流转（如 COLLECTING→COMPLETED）→ 被状态机拒绝并提示。
  3. 未登录访问 → 跳登录页。

## 3. 详细需求

### 3.1 输入

| 入口 | 操作 |
| --- | --- |
| `/admin` | 查看概览（各状态数量、待处理举报、托管余额） |
| `/admin/needs` | 需求列表 + 状态下拉强制流转 |
| `/admin/reports` | 举报处理（F20） |
| `/admin/ledger` | 资金流水（F19） |

### 3.2 输出

概览数字、需求列表（最近 50 条）、流转结果。

### 3.3 业务规则

1. **准入**：`/admin` 布局统一校验 `OPERATOR` 角色，非运营方重定向。
2. **流转复用状态机**：后台不另写规则，调用 `POST /api/needs/[id]/status`，非法流转返回明确原因。
3. **审核边界**：提案由发起者选标（F13），运营可代选；里程碑由发起者验收（F15），运营可代为验收。
4. **审计**：所有后台操作写 `AuditLog`（NEED / ADMIN）。
5. **流转到流拍必须退款**：后台把需求置为 `FAILED` 时复用 `failNeedAndRefund`，自动全额退款并收口到 `REFUNDED`（开发中/验收中需求会被拒绝，避免与结算冲突）。
6. **权限实时**：后台页面与接口的角色判断统一从数据库读取最新角色（`getSessionUser`），运营授权后无需重新登录生效。

### 3.4 状态流转

沿用 F06 状态机，后台只是操作入口，不新增流转。

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 重定向登录 |
| 普通用户 | 重定向控制台 |
| 运营方 | 概览、需求流转、举报处理、流水查看 |

## 4. 技术实现

- 涉及模块：`src/app/admin/layout.tsx`、`src/app/admin/page.tsx`、`src/app/admin/needs/page.tsx`、`src/components/admin/admin-transition.tsx`、`src/lib/auth.ts`（`getSessionUser`）
- 数据：`prisma.need.count` 按状态统计、`Report.count`、`LedgerQueryService`
- 权限：布局层与 4 个后台 API 均用 `getSessionUser()` 回源数据库校验 OPERATOR
- 外部依赖：无

## 5. 验收标准

- [x] 核心流程可用：概览、需求流转、后台导航
- [x] 异常场景有明确提示：非法流转原因、非运营方重定向
- [x] 后端权限校验（API 层）与页面准入（布局层）双重保护
- [x] 后台强制流拍会自动退款，不再出现「流拍但钱没退」
- [x] 角色判断回源数据库，运营授权即时生效
- [ ] 提案/项目的独立审核队列页面（当前通过详情页与 API 操作）

## 6. 测试要点

1. 非运营方访问被重定向。
2. 非法流转返回 INVALID_STATE。
3. 概览统计与数据库一致。
4. 所有后台操作有审计记录。
