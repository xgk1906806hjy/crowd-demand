## 1. 功能目标

为涉及资金的用户建立真实身份绑定，满足合规要求（实名 + 额度限制）。核心约束：**身份证号绝不明文落库**，且**一个身份证号只能绑定一个账号**，防止一人多号刷单、刷票、超额承诺。

## 2. 用户故事

- 作为登录用户，我想要提交真实姓名和身份证号完成实名，以便获得做付费承诺、发布需求的资格。
- 作为已实名用户，我想要看到自己的认证状态和脱敏后的实名信息，以便确认认证结果。
- 作为被拒绝的用户，我想要看到明确的失败原因并能重新提交，以便修正信息。
- 边界场景：
  - 身份证号格式/校验码错误 → 直接拒绝，不调用核验接口。
  - 同一身份证号已被其他账号绑定 → 拒绝并提示。
  - 已实名用户重复提交 → 返回当前状态，不重复核验。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| realName | string | 是 | 2–20 个字符，中文/字母/·，去首尾空格 |
| idNumber | string | 是 | 18 位，前 17 位数字 + 末位数字或 X；校验码符合 GB 11643；出生日期合法且不晚于今天、不早于 1900 年 |

### 3.2 输出

- 提交：`{ kycStatus, verifiedAt }`。
- 查询：`{ kycStatus, realNameMasked, verifiedAt, reason }`。姓名脱敏规则：保留首字，其余替换为 `*`（如「张*」）；身份证号不返回。

### 3.3 业务规则

1. 必须已登录（F01 会话）。
2. 身份证号格式与校验码在前置校验阶段拦截，不通过则不调用核验适配器、不落库。
3. 身份证号使用 **HMAC-SHA256** 计算哈希（密钥取 `KYC_HASH_SECRET`，缺省回退 `AUTH_SECRET`），仅存 `User.kycIdNumberHash` 与 `KycRecord.idNumberHash`，**禁止明文**。
4. 一人一号：`User.kycIdNumberHash` 唯一索引；若该哈希已绑定其他用户，返回冲突错误。
5. 认证状态流转：NONE → PENDING（提交）→ VERIFIED / REJECTED；REJECTED 可再次提交回到 PENDING。
6. 已 VERIFIED 用户再次提交直接返回当前状态，不重复调用核验。
7. KYC 适配器通过接口注入；MVP 用 Mock（姓名含「拒绝」则模拟核验失败，用于测试）。
8. 所有 KYC 事件写审计日志（`AuditAction.KYC`），不得物理删除。
9. 对外提供 `KycService.assertVerified(userId)`，供资金功能（F09 等）在操作前强制校验。

### 3.4 状态流转

```
NONE ──提交──> PENDING ──核验通过──> VERIFIED
                    │
                    └──核验失败──> REJECTED ──重新提交──> PENDING
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 访客 | 不可访问 |
| 已登录用户 | 提交本人实名、查询本人认证状态 |
| 运营方 | 可查看认证记录（归入 F18 后台） |

## 4. 技术实现

- 涉及模块：
  - `src/lib/id-number.ts` —— 身份证号格式与校验码校验、派生出生日期/性别
  - `src/domain/kyc/hash.ts` —— HMAC 哈希
  - `src/domain/kyc/service.ts` —— KycService（提交/查询/assertVerified）
  - `src/infrastructure/kyc/gateway.ts` —— KycGateway 接口 + Mock 实现
  - `src/app/api/kyc/{submit,status}/route.ts`
  - `src/app/(console)/console/kyc/page.tsx` —— 实名页
- 数据库变更：
  - `User` 新增 `kycIdNumberHash String? @unique`（一人一号唯一约束）
  - 复用 `KycRecord`（realName、idNumberHash、provider、status、reason）
- 外部依赖：实名核验走 `KycGateway` 适配器，MVP 用 Mock。
- 资金操作：本功能不涉及资金，但为资金功能提供 `assertVerified` 前置闸门。

## 5. 验收标准

- [x] 提交实名 → 状态变为 VERIFIED，User.kycStatus 同步
- [x] 身份证格式/校验码错误被拒绝，且有明确提示
- [x] 同一身份证号绑定第二个账号被拒绝
- [x] 身份证号明文不出现在数据库与任何 API 响应中
- [x] 核验失败进入 REJECTED 并可重新提交
- [x] 单元测试通过
- [ ] Playwright E2E（待 M2 全链路统一补）

## 6. 测试要点

- 身份证校验：合法号通过；位数不足、含非法字符、校验码错误、出生日期非法（2 月 30 日）全部拒绝。
- 哈希：同一身份证号哈希稳定；不同密钥产生不同哈希；数据库中无明文。
- 一人一号：用同一身份证号给第二个用户提交 → 冲突。
- 状态流转：NONE→VERIFIED；NONE→REJECTED→重新提交→VERIFIED。
- 幂等：已实名用户重复提交不产生新的 VERIFIED 记录堆积。
- 脱敏：返回值中姓名脱敏、身份证号不返回。
