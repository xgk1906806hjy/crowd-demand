## 1. 功能目标

验收通过后，把该节点对应的金额从托管账户精确释放给开发者，并留下可对账的 Payout 与账本流水，保证「验收多少、放多少、账上看得见」。

## 2. 用户故事

- 作为开发者，我想在节点验收后立刻收到该节点款项，以便持续投入。
- 作为运营方，我想核对每笔放款对应的节点与账本流水，以便对账。
- 边界场景：
  1. 同一节点重复验收 → 状态已变，拒绝重复放款。
  2. 放款金额为 0 → 拆分阶段已拦截（比例 >0）。
  3. 托管余额不足 → 账本出现负余额，应告警（MVP 由拆分金额 ≤ 报价保证）。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| projectId | string | 项目 |
| milestoneId | string | 节点，幂等键 `payout:{milestoneId}` |
| payeeId | string | 中标开发者 |
| amount | bigint | 节点 `releaseAmount`（分） |
| gatewayRef | string \| null | 托管方放款流水号（事务外调用回执） |
| provider | string | 实际支付适配器标识（禁止硬编码 mock） |

### 3.2 输出

`Payout` 记录（含 `gatewayRef`）+ `PaymentOrder(RELEASE)` + 两条账本分录（ESCROW DEBIT / BUILDER CREDIT）+ 项目 `releasedAmount` 自增。

### 3.3 业务规则

1. **只从托管出账**：`ESCROW → BUILDER`，不触碰其他账户。
2. **幂等**：`Payout.idempotencyKey = payout:{milestoneId}` 唯一。
3. **同事务**：节点置 `RELEASED`、写 Payout、记账、项目累加必须原子完成。
4. **金额来源**：拆分时已确定，验收时不可修改。
5. **审计**：写 `AuditLog`（PAYOUT，含 payoutId 与金额）。
6. **外部出款走适配器**：事务外先调用 `PaymentGateway.release`，reference 固定 `payout:{milestoneId}`，网关需按 reference 幂等；回执写入 Payout 与 PaymentOrder。
7. **失败可重试**：外部调用失败时节点回滚为待验收、不记账；数据库事务失败时同样回滚认领，重试复用同一 reference，不会二次出款。

### 3.4 状态流转

```
ACCEPTED ──放款成功──→ RELEASED
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 系统 | 验收通过时自动放款 |
| 运营方 | 查看放款记录 |
| 开发者 | 查看自己的收款 |

## 4. 技术实现

- 涉及模块：`src/domain/payout/service.ts`（`releaseMilestoneInTx`）、`src/domain/milestone/service.ts`（`accept` 中的通道调用）
- 复用：`postTransfer`（F10 复式账本）
- 事务：记账 + Payout + 状态由 `MilestoneService.accept` 的事务包裹
- 外部依赖：`PaymentGateway.release`（MVP Mock；生产接持牌机构出款接口）
- 账本护栏：托管余额不足时记账抛错，事务回滚、节点回到待验收

- [x] 单元测试通过：`tests/unit/milestone-service.test.ts`（放款断言）

## 6. 测试要点

1. 验收第一节点后：Payout 1 条、账本 2 条、`releasedAmount` = 节点金额。
2. 重复验收被状态机拦截，不产生第二条 Payout。
3. 放款金额等于拆分时确定的 `releaseAmount`。
4. 托管余额不足时不产生 Payout 与分录，节点保持 `SUBMITTED`。
5. `PaymentOrder(RELEASE)` 的 `gateway` 等于注入的适配器标识。
