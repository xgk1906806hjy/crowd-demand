## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：PRD 5.5 要求「验收通过后按里程碑比例放款」。
- 改动内容：
  - 新增 `src/domain/payout/service.ts` 的 `releaseMilestoneInTx()`。
  - 资金路径：`ESCROW DEBIT → BUILDER CREDIT`，复用 `postTransfer` 复式记账。
  - `Payout.idempotencyKey = payout:{milestoneId}`，防重复放款。
  - 节点置 RELEASED、项目 `releasedAmount` 自增，均在验收事务内完成。
- 影响范围：
  - 开发者收款账户余额可通过账本推导。
  - 托管余额随放款递减，结算后归零。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：111 用例全绿（放款断言：Payout 1 条、账本 2 条、金额 40000）
  - `npm run build`：EXIT=0（最终全量构建 41 条路由全部生成）

### v0.2 — 2026-11-23 — Bug 修复

- 背景：`releaseMilestoneInTx` 只写账本与 Payout，`gatewayRef` 恒为 null，出款从未经过支付适配器。
- 改动内容：
  - `MilestoneService` 注入 `PaymentGateway`，验收时以 `payout:{milestoneId}` 调用 `release`，回执传入事务。
  - `releaseMilestoneInTx` 新增 `gatewayRef` / `provider`，写 `Payout` 与 `PaymentOrder(RELEASE)`，不再硬编码 mock。
  - 托管余额不足时记账抛错 → 事务回滚 → 认领回滚。
- 验证方式：里程碑测试断言 `Payout.gatewayRef` 非空、RELEASE 分录 2 条、订单 provider 为注入值。
