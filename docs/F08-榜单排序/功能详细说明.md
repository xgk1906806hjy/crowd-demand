## 1. 功能目标

把「零成本的票」和「真金白银的承诺」分成两个独立榜单展示，让用户一眼看出哪些需求呼声高、哪些需求已经有人愿意付钱，避免用票数掩盖付费意愿不足。

## 2. 用户故事

- 作为路人，我想看热度榜，以便知道大家在关心什么。
- 作为潜在支持者，我想看承诺榜，以便判断哪些需求真的有人愿意买单。
- 作为发起者，我想知道自己的需求在榜单上的位置，以便决定是否继续推广。
- 边界场景：
  1. 传 `sort=xxx` → 回退热度榜，不报错。
  2. 两个需求票数相同 → 按发布时间倒序，再按 id 保证稳定分页。
  3. 目标金额为 0 的需求 → 进度显示 0%，不出现除零。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| sort | hot / pledge / latest / deadline | 否 | 非法值回退 hot |
| limit | number | 否 | 首页取 3-6 条 |

### 3.2 输出

按口径排序的 `NeedListItemView[]`，含票数、已承诺金额、进度。

### 3.3 业务规则

1. **四个口径**：热度（voteCount desc）、承诺（pledgedAmount desc）、最新（publishedAt desc）、即将截止（deadline asc）。
2. **稳定排序**：每个口径都追加次级排序（id asc），避免分页重复/漏项。
3. **两个榜单独立**：首页并列展示「热度榜」与「承诺榜」，不混算综合分（避免用票数稀释付费信号）。
4. **榜单排除草稿**。
5. **承诺榜数据来源**：`Need.pledgedAmount` 由 F09 维护，本功能只读。

### 3.4 状态流转

无（纯读功能）。

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 查看全部公开榜单 |
| 已登录 | 同上 |
| 运营方 | 同上 |

## 4. 技术实现

- 涉及模块：`src/domain/need/query.ts`（`buildNeedOrderBy`、`normalizeSort`、`computeProgress`、`NeedQueryService.top`）、`src/app/(public)/needs/page.tsx`、`src/app/page.tsx`
- 数据库变更：`Need.pledgedAmount` + `@@index([status, pledgedAmount])`
- 性能：榜单依赖冗余字段与复合索引，避免每次 `COUNT(votes)` 聚合
- 外部依赖：无

## 6. 测试要点

1. `normalizeSort` 对 null/非法值回退 hot。
2. 四种口径首项排序字段与方向正确。
3. 每种排序 `orderBy` 长度 > 1（含次级排序）。
4. 进度：0、50、25、33.3、200、目标 0。
5. 首页两个榜单独立取数，互不影响。
