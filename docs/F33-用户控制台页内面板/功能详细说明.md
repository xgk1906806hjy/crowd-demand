## 1. 功能目标

把用户控制台从「一排按钮各自跳转到独立子页面」改为「单页内 Tab 切换全部模块」，让用户在控制台里连续查看与操作，不必每次点击都整页跳转、丢失上下文。

## 2. 用户故事

- 作为登录用户，我想在控制台里直接切换查看「实名认证 / 角色与信誉 / 我的需求 / 我的承诺 / 我的提案」，以便不离开控制台就能处理自己的事。
- 作为发布者，我想在控制台内直接进入发布需求表单，不再跳转到另一页。
- 边界场景：未实名用户切到「发布需求」时，页内提示先认证并可一键切到「实名认证」Tab；数据库不可用时，页内提示「部分数据暂时无法加载」而不是整页报错。

## 3. 详细需求

### 3.1 输入

控制台服务端一次性查询并下传：

| 数据 | 来源 | 校验规则 |
| --- | --- | --- |
| 用户资料 | `prisma.user`（phone/email/nickname/roles/kycStatus/reputationScore） | 无会话则 302 到 `/login` |
| 我的需求 | `NeedService.listMine` | 失败时置空并标记 dbError |
| 我的承诺 | `PledgeService.listMine` | 同上 |
| 我的提案 | `ProposalService.listMine` | 同上 |

### 3.2 输出

单页 7 个 Tab：概览、实名认证、角色与信誉、我的需求、我的承诺、我的提案、发布需求。

- 概览：账号信息表 + 4 个统计卡（需求数、托管中承诺金额、提案数、实名状态）+ 快捷按钮。
- 实名认证：复用 `KycPanel`（状态查询、提交表单；认证成功后 `router.refresh()` 同步外层状态）。
- 角色与信誉：复用 `RolePanel`（角色申请 + 安全设置）。
- 我的需求 / 承诺 / 提案：复用原列表卡片与状态文案，点击卡片进入需求详情（内容详情页，属正常阅读路径）。
- 发布需求：已实名直接内嵌 `NewNeedForm`；未实名在页内提示并可切到实名 Tab。

### 3.3 业务规则

1. 点击 Tab 不改变路由，不触发整页跳转。
2. 控制台模块入口不再使用 `<Link>`；仅「去需求广场」与需求详情卡片保留链接（跨出控制台范围的内容页）。
3. 所有面板共用一次服务端查询结果，避免每个 Tab 各发一次请求。
4. 旧子路由（`/console/kyc`、`/console/profile`、`/console/needs`、`/console/pledges`、`/console/proposals`、`/console/needs/new`）保留可用，兼容旧链接与书签。

### 3.4 状态流转

不涉及业务状态机；仅前端 Tab 选中态（组件本地 `useState`）。

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 无法进入控制台（middleware 302 到登录页） |
| 登录用户 | 查看与操作全部 Tab（发布需求仍需实名） |

## 4. 技术实现

- 前端：`src/components/console/console-dashboard.tsx`（Tab 容器 + 三个列表面板）、`src/components/console/kyc-panel.tsx`、`src/components/console/role-panel.tsx`、`src/components/need/new-need-form.tsx`（从发布页抽出复用）
- 页面：`src/app/(console)/console/page.tsx`（服务端一次查询）；`/console/kyc`、`/console/profile`、`/console/needs/new` 改为薄壳复用组件
- 数据库变更：无
- 外部依赖：无

## 6. 测试要点

- 概览统计与真实数据一致（需求数 / 托管中金额 / 提案数 / 实名状态）。
- 每个 Tab 切换后不出现 404、不重置外层用户状态。
- 实名认证提交成功后切回概览，实名状态更新。
- dbError 时页面不崩溃，提示文案出现。
- 未实名时「发布需求」Tab 不渲染表单，点击「去认证」切到实名 Tab。
