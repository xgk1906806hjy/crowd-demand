# 部署流程

本文覆盖从零部署到日常发布的完整流程。目标环境：单台 Linux 虚拟机（内网 `192.168.100.91`），Docker Compose 部署。

---

## 1. 部署架构

```
                 80 端口
  浏览器 ──────────────────► Nginx 容器
                                 │  反向代理
                                 ▼
                          Next.js 应用容器 (:3000)
                                 │
                    ┌────────────┴────────────┐
                    ▼                         ▼
             PostgreSQL 容器             Redis 容器
              （数据卷持久化）          （队列/限流预留）
```

四个容器同处一个内部 bridge 网络，**只有 Nginx 对外暴露端口**，数据库与 Redis 不映射到宿主机，避免误暴露。

| 组件 | 镜像 | 对外端口 | 说明 |
|---|---|---|---|
| nginx | nginx:alpine | 80（可配） | 唯一入口，负责反代与限流 |
| app | 本地构建 | 无（内网 3000） | Next.js standalone |
| postgres | postgres:16-alpine | 无 | 数据存 `pgdata` 卷 |
| redis | redis:7-alpine | 无 | 当前版本仅预留 |

## 2. 环境要求

| 项目 | 最低要求 | 建议 |
|---|---|---|
| CPU | 2 核 | 2 核以上 |
| 内存 | 2 GB | 4 GB（构建阶段较吃内存） |
| 磁盘 | 10 GB | 20 GB |
| 系统 | CentOS 7+ / Ubuntu 20.04+ / Debian 11+ | Ubuntu 22.04 |
| Docker | 20.10+（含 compose 插件） | 最新稳定版 |

检查：

```bash
docker version
docker compose version
free -h && df -h
```

## 3. 首次部署（Docker Compose）

### 3.1 安装 Docker（国内网络）

```bash
# 使用阿里云镜像源安装
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable --now docker

# 配置镜像加速，避免拉取镜像超时
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
systemctl restart docker

# 验证
docker run --rm hello-world
```

> 如果服务器无法访问外网，需要在能联网的机器上 `docker save` 镜像后 `docker load` 导入，或搭建私有 Registry。

### 3.2 获取代码

**方式 A：从 Git 仓库克隆（服务器能访问 GitHub 时）**

```bash
mkdir -p /opt && cd /opt
git clone https://github.com/xgk1906806hjy/crowd-demand.git
cd crowd-demand
```

**方式 B：本地打包上传（内网服务器常用）**

在开发机上执行：

```bash
# 排除依赖与构建产物，只传源码
tar --exclude=node_modules --exclude=.next --exclude=.git \
    -czf crowd-demand.tar.gz -C /e/workspace crowd-demand

scp crowd-demand.tar.gz <用户名>@192.168.100.91:/opt/
```

服务器上解压：

```bash
cd /opt && tar -xzf crowd-demand.tar.gz && cd crowd-demand
```

### 3.3 配置环境变量

```bash
cp deploy/.env.production.example deploy/.env.production

# 生成强随机密钥
openssl rand -base64 48

# 编辑配置
vi deploy/.env.production
```

必须修改的三项：

```ini
POSTGRES_PASSWORD=<强密码，不要用 crowd>
AUTH_SECRET=<上一步 openssl 生成的字符串>
NEXT_PUBLIC_APP_URL=http://192.168.100.91
```

**注意**：`SMS_ADAPTER` / `KYC_ADAPTER` / `PAYMENT_ADAPTER` 保持 `mock` 时，短信不会真实发送、支付不会真实扣款。用于演示和内部测试足够；正式对外运营前必须接入真实服务，否则用户无法完成注册与付款。

还需要注意两项：

```ini
# 内部定时结算（到期退款/放款）的调用密钥，≥16 字符
CRON_SECRET=<openssl rand -hex 24>

# 生产语义下 PAYMENT_ADAPTER 不允许为 mock，否则应用拒绝启动
# 内部演示实例请显式声明 demo
APP_ENV=demo
```

`APP_ENV` 是**显式的合规开关**：默认 `production`，此时若 `NODE_ENV=production` 且支付适配器仍是 `mock`，应用启动即抛错（`deploy.sh` 也会提前拦下）。只有显式写 `APP_ENV=demo` 才会放行，并在日志中持续打印告警——该实例严禁接入真实资金。

#### 3.3.1 接入真实验证码通道（可选，2026-11-23 起支持）

默认 `SMS_ADAPTER=mock` / `EMAIL_ADAPTER=mock`（验证码打印在应用日志）。要真实发送，编辑 `deploy/.env.production` 后重跑 `deploy/deploy.sh` 即可，**无需改代码、无新增依赖**。

**真实邮件（最简单，免费）**：用 QQ/163 邮箱的 SMTP 授权码。

```ini
EMAIL_ADAPTER=smtp
SMTP_HOST=smtp.qq.com        # 163 邮箱填 smtp.163.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=你的QQ号@qq.com
SMTP_PASS=<SMTP授权码>        # QQ：设置→账号→开启SMTP服务生成；163：设置→POP3/SMTP。不是邮箱登录密码！
# SMTP_FROM 缺省等于 SMTP_USER
```

**真实短信（二选一）**：需云账号 + 控制台审核通过的签名与模板（个人可申请，审核约 1-2 天）。短信按条计费（约 0.045 元/条）。

```ini
# 阿里云（模板变量形如 ${code}）
SMS_ADAPTER=aliyun
ALIYUN_SMS_ACCESS_KEY_ID=<RAM 用户 AccessKey，建议只授 Dysmsapi 权限>
ALIYUN_SMS_ACCESS_KEY_SECRET=<对应 Secret>
ALIYUN_SMS_SIGN_NAME=<审核通过的签名>
ALIYUN_SMS_TEMPLATE_CODE=<模板CODE，如 SMS_123456789>
# ALIYUN_SMS_TEMPLATE_PARAM 缺省 code，与模板变量名一致即可

# 或腾讯云（模板变量为 {1}）
SMS_ADAPTER=tencent
TENCENT_SMS_SECRET_ID=<API 密钥 SecretId>
TENCENT_SMS_SECRET_KEY=<对应 SecretKey>
TENCENT_SMS_SDK_APP_ID=<短信应用 SdkAppId>
TENCENT_SMS_SIGN_NAME=<审核通过的签名>
TENCENT_SMS_TEMPLATE_ID=<模板ID>
# TENCENT_SMS_REGION 缺省 ap-guangzhou
```

注意事项：

- 缺配置时应用启动即抛中文错误并列出缺失变量名，不会静默回退 Mock。
- 真实通道日志**不打印验证码**；`deploy/smoke-auth.sh` 依赖从日志抓 Mock 码，切真实通道后该脚本的验证码登录部分不再适用（密码登录部分仍可用）。
- 服务器需能出公网访问 `smtp.qq.com:465` / `dysmsapi.aliyuncs.com:443` / `sms.tencentcloudapi.com:443`。
- 演示实例（`APP_ENV=demo`）切真实通道同样生效；`production` 下 Mock 仍被禁止。

### 3.4 启动

```bash
chmod +x deploy/deploy.sh
./deploy/deploy.sh
```

脚本会依次完成：校验环境 → 构建镜像 → 启动容器 → 等待健康检查通过 → 输出访问地址。

首次构建约 3–6 分钟（取决于网络与机器性能）。

也可以手动执行：

```bash
docker compose -f docker-compose.prod.yml --env-file deploy/.env.production up -d --build
```

### 3.7 端到端冒烟测试

部署后建议立刻跑一遍真实链路（注册 → 实名 → 发需求 → 投票 → 付费承诺 → 竞标 → 提案 → 选标 → 交付 → 验收）：

```bash
./deploy/smoke.sh                        # 默认打 127.0.0.1:8000
./deploy/smoke.sh http://192.168.100.91:8000
```

脚本用真实 HTTP 调用，并自动核对票数累加、承诺幂等、达标自动进入竞标、验收触发放款等关键行为。**必须在部署机执行**：Mock 短信把验证码打印在应用日志里，脚本需要读取日志才能登录（`APP_ENV=demo` 下才会打印）。

输出示例：

```
[smoke] 目标地址：http://127.0.0.1:8000
  ✓ 健康检查
  ✓ 发送验证码（发起者）
  ...
[smoke] 全部通过：42 项检查
```

脚本会创建真实数据（三个测试手机号 + 一条测试需求）。正式环境请勿随意执行，或先清理数据。

有偿悬赏与无偿认领走另一套专项冒烟（发布 → 全额托管 → 提案额度 → 禁止众筹投票 → 撤回退款 → 无偿零报价）：

```bash
./deploy/smoke-f28.sh                    # 默认打 127.0.0.1:8000
```

预期输出 `[f28] 结果：通过 33 项，失败 0 项`。该脚本会顺带核对 `BountyEscrow` 行、托管账户净额与退款复式流水。

## 4. 手动部署（不使用 Docker）

适用于禁止使用容器的环境。

### 4.1 安装依赖

```bash
# Node.js 22
curl -fsSL https://rpm.nodesource.com/setup_22.x | bash -   # CentOS
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -   # Ubuntu/Debian
apt install -y nodejs        # 或 yum install -y nodejs

# PostgreSQL 16
apt install -y postgresql postgresql-contrib
systemctl enable --now postgresql

# 建库建用户
sudo -u postgres psql <<'SQL'
CREATE USER crowd WITH PASSWORD '强密码';
CREATE DATABASE crowd_demand OWNER crowd;
SQL
```

### 4.2 构建与启动

```bash
cd /opt/crowd-demand
npm ci --registry=https://registry.npmmirror.com

# 生成 Prisma Client（网络受限时指定镜像）
PRISMA_ENGINES_MIRROR=https://npmmirror.com/mirrors/prisma npx prisma generate

npm run build

# 同步数据库结构
npx prisma db push --skip-generate

# 用 PM2 常驻
npm install -g pm2
pm2 start npm --name crowd-demand -- start
pm2 save && pm2 startup
```

### 4.3 Nginx 反代

使用仓库内的 `deploy/nginx.conf`，把 `server app:3000;` 改为 `server 127.0.0.1:3000;`：

```bash
cp deploy/nginx.conf /etc/nginx/conf.d/crowd-demand.conf
sed -i 's/server app:3000;/server 127.0.0.1:3000;/' /etc/nginx/conf.d/crowd-demand.conf
nginx -t && systemctl reload nginx
```

## 5. 数据库管理与迁移

### 当前状态：构建期生成 SQL，部署期幂等应用

运行镜像采用 Next standalone 输出，只保留运行时依赖，**没有完整 Prisma CLI 依赖树**（在容器里跑 `prisma db push` 会因缺 `effect` 等模块直接崩溃）。因此建表不在应用容器内做，而是分三步：

1. **生成 SQL**（开发机执行，产物随仓库提交）：

   ```bash
   npx prisma migrate diff \
     --from-empty \
     --to-schema-datamodel prisma/schema.prisma \
     --script > prisma/init.sql
   ```

2. **部署时应用**：`deploy/deploy.sh` 在启动应用前先起 postgres，检查 `public."User"` 表是否存在；不存在则用 `psql -f -` 应用 `prisma/init.sql`（整文件包在一个事务里，中途失败自动回滚），已存在则跳过，因此可重复执行。

3. **手工补跑**：

   ```bash
   ./deploy/deploy.sh migrate
   ```

> **改动 `schema.prisma` 后必须重新生成 `prisma/init.sql`**，否则新建的库会缺表。这是当前唯一的 schema 分发路径。

### 推荐：转为正式的迁移流程

`init.sql` 解决了“新库一次建好”，但**不保留变更历史**。正式上线前建议切换到 `prisma migrate`：

```bash
# 开发机：基于当前 schema 生成首个迁移
npx prisma migrate dev --name init
git add prisma/migrations && git commit -m "chore: 初始化数据库迁移"
```

此后 schema 变更一律走 `migrate dev`，生产执行 `prisma migrate deploy`（需在带 Prisma CLI 的环境运行，例如开发机直连生产库，或一次性 `node:22-slim` 容器挂载源码）。届时把 `deploy.sh` 的 `ensure_schema` 换成 `migrate deploy` 调用即可。

### 进入数据库

```bash
docker compose -f docker-compose.prod.yml exec postgres \
  psql -U crowd -d crowd_demand
```

### 常用排查 SQL

```sql
-- 表是否建好
\dt

-- 需求与状态分布
SELECT status, count(*) FROM "Need" GROUP BY status;

-- 资金总额核对（账本借贷平衡）
SELECT "account", sum(CASE WHEN direction = 'CREDIT' THEN amount ELSE -amount END)
FROM "LedgerEntry" GROUP BY "account";

-- 有未达标但未退款的承诺
SELECT id, "needId", amount FROM "Pledge" WHERE status = 'HELD';
```

## 6. 版本更新

```bash
cd /opt/crowd-demand

# 1. 备份数据库（务必先做）
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U crowd crowd_demand > backup-$(date +%F-%H%M).sql

# 2. 拉取新代码
git pull

# 3. 重新构建并滚动重启
./deploy/deploy.sh

# 4. 验证
curl http://192.168.100.91/api/health
```

数据库结构变更由 entrypoint 自动处理。若涉及破坏性变更（删字段、改类型），需先评估数据迁移方案。

## 7. 备份与恢复

### 数据库备份

```bash
# 手动备份
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U crowd -Fc crowd_demand > /opt/backup/crowd-$(date +%F).dump

# 定时备份（每天 3:00，保留 14 天）
cat >> /etc/cron.d/crowd-backup <<'EOF'
0 3 * * * root mkdir -p /opt/backup && docker compose -f /opt/crowd-demand/docker-compose.prod.yml exec -T postgres pg_dump -U crowd -Fc crowd_demand > /opt/backup/crowd-$(date +\%F).dump && find /opt/backup -name 'crowd-*.dump' -mtime +14 -delete
EOF
```

### 恢复

```bash
# 停止应用，避免写入
docker compose -f docker-compose.prod.yml stop app

# 重建库并导入
docker compose -f docker-compose.prod.yml exec -T postgres \
  psql -U crowd -d postgres -c "DROP DATABASE crowd_demand;" -c "CREATE DATABASE crowd_demand OWNER crowd;"
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_restore -U crowd -d crowd_demand < /opt/backup/crowd-2026-11-23.dump

docker compose -f docker-compose.prod.yml start app
```

> **资金数据尤其重要**：`Pledge`、`LedgerEntry`、`Payout` 三张表一旦丢失无法从业务侧重建，备份策略必须覆盖。

## 10. 常见问题

**新增字段后接口报 `column "mode" does not exist`（Prisma P2022）**

`deploy.sh` 的 `ensure_schema` 只在 `public."User"` 不存在时才应用 `prisma/init.sql`，**既有库不会自动补新增列/表**。凡是改了 `prisma/schema.prisma`，都要同步写一份幂等增量脚本 `prisma/patches/<日期>-<功能>.sql`，并在发布时手工执行：

```bash
docker compose -f docker-compose.prod.yml --env-file deploy/.env.production exec -T postgres \
  psql -v ON_ERROR_STOP=1 -U crowd -d crowd_demand -f - < prisma/patches/2026-11-23-f28-bounty.sql
```

脚本用 `ADD COLUMN IF NOT EXISTS` / `CREATE TABLE IF NOT EXISTS` 保护，可重复执行。

**构建卡在 `Collecting page data`**

内存不足导致并行 worker 挂起。`next.config.mjs` 已设置 `experimental.cpus: 1`；若仍出现，构建时加 `NODE_OPTIONS=--max-old-space-size=2048`，或临时增加 swap：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```

**`npm ci` 卡住或 Prisma 引擎下载失败**

国内网络访问 `binaries.prisma.sh` 经常超时：

```bash
npm ci --registry=https://registry.npmmirror.com
PRISMA_ENGINES_MIRROR=https://npmmirror.com/mirrors/prisma npx prisma generate
```

Dockerfile 中同理，可在 `RUN` 前加 `ENV PRISMA_ENGINES_MIRROR=...`。

**容器启动后 `/api/health` 返回 503（db: down）**

说明应用起来了但连不上数据库。检查：

```bash
docker compose -f docker-compose.prod.yml logs postgres | tail -30
docker compose -f docker-compose.prod.yml exec app node -e "console.log(process.env.DATABASE_URL)"
```

常见原因：密码含特殊字符未转义（`@`、`#` 需 URL 编码）、postgres 容器未 healthy 就启动了 app。

**容器反复重启，日志报 `Cannot find module 'effect'` 或 `@prisma/config`**

容器内执行了 Prisma CLI（`db push` / `migrate deploy`），而 standalone 镜像只含运行时依赖，CLI 的依赖树不完整。不要在运行容器里跑 Prisma CLI，改用 SQL 方案：

```bash
./deploy/deploy.sh migrate     # 应用 prisma/init.sql
```

**启动即退出，日志报“合规红线：生产环境禁止使用 mock 支付适配器”**

这是预期行为。`NODE_ENV=production` 且 `PAYMENT_ADAPTER=mock` 时应用拒绝启动。正式环境请接入持牌机构适配器并设置 `PAYMENT_ADAPTER=licensed`；仅内部演示时设 `APP_ENV=demo`（日志会持续告警）。

**登录收不到验证码**

`SMS_ADAPTER=mock` 时验证码不会真实发送，只写日志：

```bash
./deploy/deploy.sh logs app | grep -i "验证码\|code"
```

**页面 502 Bad Gateway**

Nginx 起来了但应用没起来：

```bash
docker compose -f docker-compose.prod.yml ps
./deploy/deploy.sh logs app | tail -50
```

**`crowd-demand-cron` 一直显示 `unhealthy`，但日志里 `cron status 200` 正常**

cron 容器复用 `crowd-demand-app:local` 镜像，因此**继承了镜像内置的 `HEALTHCHECK`（探测容器自身的 :3000）**，而 cron 容器里并没有应用进程，探针必然失败。它不是业务故障，但会让 `docker ps` 长期报警。`docker-compose.prod.yml` 的 cron 服务已声明：

```yaml
healthcheck:
  disable: true
```

若你改过镜像或用旧版 compose 文件，请确认该项仍在。

**构建卡在 `npm ci` 长时间无输出**

国内网络直连 `registry.npmjs.org` 与 `binaries.prisma.sh` 都可能长时间停滞（实测下载速率可低至十几 KB/s），表现为 `npm ci` 进程 CPU 时间不再增长、构建日志停在 `#10 RUN npm ci` 不动。处置顺序：

1. 耐心等待：一旦网络恢复到百 KB/s 级，`npm ci` 约 90 秒可完成，不必中断。
2. 判断是否真挂死（CPU 时间 20 秒内不增长即视为停滞）：

   ```bash
   ps aux | grep "npm ci" | grep -v grep
   ```

3. 确认卡死后，临时改用镜像源重试：把 `Dockerfile` 中 `RUN npm ci --no-audit --no-fund` 改为
   `RUN npm ci --no-audit --no-fund --registry=https://registry.npmmirror.com`，再执行 `./deploy/deploy.sh`。
   实测不同镜像速率差异极大（华为云 `mirrors.huaweicloud.com/repository/npm` 可达 270 KB/s，腾讯云约 21 KB/s）。
   注意 `package-lock.json` 未变时该层可命中 Docker 构建缓存，改动 `Dockerfile` 文本反而会使缓存失效，因此**能等到就别改**。

**`bad interpreter: /bin/sh^M`**

脚本被 Windows 换行符污染。仓库已通过 `.gitattributes` 强制 `*.sh` 使用 LF；若手工拷贝文件，执行：

```bash
sed -i 's/\r$//' deploy/deploy.sh deploy/entrypoint.sh
```
