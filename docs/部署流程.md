# 部署流程

本文覆盖从零部署到日常发布的完整流程。目标环境：单台 Linux 虚拟机（内网 `192.168.100.91`），Docker Compose 部署。

---

## 1. 部署架构

```
                 80 端口
  浏览器 ──────────────────► Nginx 容器
                                 │  反向代理
                                 ▼
                          Next.js 应用容器 (:3000)
                                 │
                    ┌────────────┴────────────┐
                    ▼                         ▼
             PostgreSQL 容器             Redis 容器
              （数据卷持久化）          （队列/限流预留）
```

四个容器同处一个内部 bridge 网络，**只有 Nginx 对外暴露端口**，数据库与 Redis 不映射到宿主机，避免误暴露。

| 组件 | 镜像 | 对外端口 | 说明 |
|---|---|---|---|
| nginx | nginx:alpine | 80（可配） | 唯一入口，负责反代与限流 |
| app | 本地构建 | 无（内网 3000） | Next.js standalone |
| postgres | postgres:16-alpine | 无 | 数据存 `pgdata` 卷 |
| redis | redis:7-alpine | 无 | 当前版本仅预留 |

## 2. 环境要求

| 项目 | 最低要求 | 建议 |
|---|---|---|
| CPU | 2 核 | 2 核以上 |
| 内存 | 2 GB | 4 GB（构建阶段较吃内存） |
| 磁盘 | 10 GB | 20 GB |
| 系统 | CentOS 7+ / Ubuntu 20.04+ / Debian 11+ | Ubuntu 22.04 |
| Docker | 20.10+（含 compose 插件） | 最新稳定版 |

检查：

```bash
docker version
docker compose version
free -h && df -h
```

## 3. 首次部署（Docker Compose）

### 3.1 安装 Docker（国内网络）

```bash
# 使用阿里云镜像源安装
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable --now docker

# 配置镜像加速，避免拉取镜像超时
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
systemctl restart docker

# 验证
docker run --rm hello-world
```

> 如果服务器无法访问外网，需要在能联网的机器上 `docker save` 镜像后 `docker load` 导入，或搭建私有 Registry。

### 3.2 获取代码

**方式 A：从 Git 仓库克隆（服务器能访问 GitHub 时）**

```bash
mkdir -p /opt && cd /opt
git clone https://github.com/xgk1906806hjy/crowd-demand.git
cd crowd-demand
```

**方式 B：本地打包上传（内网服务器常用）**

在开发机上执行：

```bash
# 排除依赖与构建产物，只传源码
tar --exclude=node_modules --exclude=.next --exclude=.git \
    -czf crowd-demand.tar.gz -C /e/workspace crowd-demand

scp crowd-demand.tar.gz <用户名>@192.168.100.91:/opt/
```

服务器上解压：

```bash
cd /opt && tar -xzf crowd-demand.tar.gz && cd crowd-demand
```

### 3.3 配置环境变量

```bash
cp deploy/.env.production.example deploy/.env.production

# 生成强随机密钥
openssl rand -base64 48

# 编辑配置
vi deploy/.env.production
```

必须修改的三项：

```ini
POSTGRES_PASSWORD=<强密码，不要用 crowd>
AUTH_SECRET=<上一步 openssl 生成的字符串>
NEXT_PUBLIC_APP_URL=http://192.168.100.91
```

**注意**：`SMS_ADAPTER` / `KYC_ADAPTER` / `PAYMENT_ADAPTER` 保持 `mock` 时，短信不会真实发送、支付不会真实扣款。用于演示和内部测试足够；正式对外运营前必须接入真实服务，否则用户无法完成注册与付款。

### 3.4 启动

```bash
chmod +x deploy/deploy.sh
./deploy/deploy.sh
```

脚本会依次完成：校验环境 → 构建镜像 → 启动容器 → 等待健康检查通过 → 输出访问地址。

首次构建约 3–6 分钟（取决于网络与机器性能）。

也可以手动执行：

```bash
docker compose -f docker-compose.prod.yml --env-file deploy/.env.production up -d --build
```

### 3.5 验证

```bash
# 1. 容器状态：app 应为 healthy
./deploy/deploy.sh status

# 2. 健康检查：应返回 db="up"
curl http://192.168.100.91/api/health

# 期望输出：
# {"status":"ok","db":"up","latencyMs":3,"uptimeSec":12,...}

# 3. 页面访问
curl -o /dev/null -w "%{http_code}\n" http://192.168.100.91/
curl -o /dev/null -w "%{http_code}\n" http://192.168.100.91/needs
```

浏览器打开 `http://192.168.100.91`，应能看到需求广场首页。

### 3.6 写入演示数据（可选）

容器内没有 `tsx`，演示数据建议在开发机生成后导出，或临时用 Node 执行：

```bash
# 在服务器上（容器内执行等价的 SQL 或使用一次性 node 容器）
docker compose -f docker-compose.prod.yml exec app \
  node -e "console.log('seed 需 tsx，建议在开发机执行 npm run db:seed 后导出数据')"
```

更简单的做法：注册一个账号，在界面里手动走完流程，数据更真实。

## 4. 手动部署（不使用 Docker）

适用于禁止使用容器的环境。

### 4.1 安装依赖

```bash
# Node.js 22
curl -fsSL https://rpm.nodesource.com/setup_22.x | bash -   # CentOS
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -   # Ubuntu/Debian
apt install -y nodejs        # 或 yum install -y nodejs

# PostgreSQL 16
apt install -y postgresql postgresql-contrib
systemctl enable --now postgresql

# 建库建用户
sudo -u postgres psql <<'SQL'
CREATE USER crowd WITH PASSWORD '强密码';
CREATE DATABASE crowd_demand OWNER crowd;
SQL
```

### 4.2 构建与启动

```bash
cd /opt/crowd-demand
npm ci --registry=https://registry.npmmirror.com

# 生成 Prisma Client（网络受限时指定镜像）
PRISMA_ENGINES_MIRROR=https://npmmirror.com/mirrors/prisma npx prisma generate

npm run build

# 同步数据库结构
npx prisma db push --skip-generate

# 用 PM2 常驻
npm install -g pm2
pm2 start npm --name crowd-demand -- start
pm2 save && pm2 startup
```

### 4.3 Nginx 反代

使用仓库内的 `deploy/nginx.conf`，把 `server app:3000;` 改为 `server 127.0.0.1:3000;`：

```bash
cp deploy/nginx.conf /etc/nginx/conf.d/crowd-demand.conf
sed -i 's/server app:3000;/server 127.0.0.1:3000;/' /etc/nginx/conf.d/crowd-demand.conf
nginx -t && systemctl reload nginx
```

## 5. 数据库管理与迁移

### 当前状态

项目使用 `prisma db push` 同步结构（尚无 `prisma/migrations` 目录）。容器启动时 `deploy/entrypoint.sh` 会自动判断：

- 存在 `prisma/migrations/` 且非空 → 执行 `prisma migrate deploy`
- 否则 → 执行 `prisma db push --skip-generate`

### 推荐：转为正式的迁移流程

`db push` 适合开发期快速迭代，但**不保留变更历史，也不适合多人协作的生产环境**。正式上线前建议：

```bash
# 在开发机（有完整数据库）上生成迁移文件
npx prisma migrate dev --name init

# 提交 prisma/migrations/ 目录到仓库
git add prisma/migrations && git commit -m "chore: 初始化数据库迁移"

# 服务器上拉取后，下次启动会自动执行 migrate deploy
```

此后所有 schema 变更都应走 `migrate dev` 生成迁移文件，而不是 `db push`。

### 进入数据库

```bash
docker compose -f docker-compose.prod.yml exec postgres \
  psql -U crowd -d crowd_demand
```

### 常用排查 SQL

```sql
-- 表是否建好
\dt

-- 需求与状态分布
SELECT status, count(*) FROM "Need" GROUP BY status;

-- 资金总额核对（账本借贷平衡）
SELECT "account", sum(CASE WHEN direction = 'CREDIT' THEN amount ELSE -amount END)
FROM "LedgerEntry" GROUP BY "account";

-- 有未达标但未退款的承诺
SELECT id, "needId", amount FROM "Pledge" WHERE status = 'HELD';
```

## 6. 版本更新

```bash
cd /opt/crowd-demand

# 1. 备份数据库（务必先做）
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U crowd crowd_demand > backup-$(date +%F-%H%M).sql

# 2. 拉取新代码
git pull

# 3. 重新构建并滚动重启
./deploy/deploy.sh

# 4. 验证
curl http://192.168.100.91/api/health
```

数据库结构变更由 entrypoint 自动处理。若涉及破坏性变更（删字段、改类型），需先评估数据迁移方案。

## 7. 备份与恢复

### 数据库备份

```bash
# 手动备份
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U crowd -Fc crowd_demand > /opt/backup/crowd-$(date +%F).dump

# 定时备份（每天 3:00，保留 14 天）
cat >> /etc/cron.d/crowd-backup <<'EOF'
0 3 * * * root mkdir -p /opt/backup && docker compose -f /opt/crowd-demand/docker-compose.prod.yml exec -T postgres pg_dump -U crowd -Fc crowd_demand > /opt/backup/crowd-$(date +\%F).dump && find /opt/backup -name 'crowd-*.dump' -mtime +14 -delete
EOF
```

### 恢复

```bash
# 停止应用，避免写入
docker compose -f docker-compose.prod.yml stop app

# 重建库并导入
docker compose -f docker-compose.prod.yml exec -T postgres \
  psql -U crowd -d postgres -c "DROP DATABASE crowd_demand;" -c "CREATE DATABASE crowd_demand OWNER crowd;"
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_restore -U crowd -d crowd_demand < /opt/backup/crowd-2026-11-23.dump

docker compose -f docker-compose.prod.yml start app
```

> **资金数据尤其重要**：`Pledge`、`LedgerEntry`、`Payout` 三张表一旦丢失无法从业务侧重建，备份策略必须覆盖。

## 8. 日志与监控

```bash

./deploy/deploy.sh logs
```

## 9. 上线检查清单

- [ ] `deploy/.env.production` 中无 `CHANGE_ME` 占位符
- [ ] `AUTH_SECRET` 长度 ≥ 32 且与开发环境不同
- [ ] `POSTGRES_PASSWORD` 为强密码
- [ ] `NEXT_PUBLIC_APP_URL` 填的是实际访问地址
- [ ] 数据库端口未映射到宿主机（`docker compose ps` 确认）
- [ ] `/api/health` 返回 `db: "up"`
- [ ] 首页、`/needs`、`/login` 均返回 200
- [ ] 已配置数据库定时备份
- [ ] 已确认支付/短信/实名适配器状态（mock 只能内部试用）
- [ ] 已阅读 `README.md` 的合规声明

## 10. 常见问题

**构建卡在 `Collecting page data`**

内存不足导致并行 worker 挂起。`next.config.mjs` 已设置 `experimental.cpus: 1`；若仍出现，构建时加 `NODE_OPTIONS=--max-old-space-size=2048`，或临时增加 swap：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```

**`npm ci` 卡住或 Prisma 引擎下载失败**

国内网络访问 `binaries.prisma.sh` 经常超时：

```bash
npm ci --registry=https://registry.npmmirror.com
PRISMA_ENGINES_MIRROR=https://npmmirror.com/mirrors/prisma npx prisma generate
```

Dockerfile 中同理，可在 `RUN` 前加 `ENV PRISMA_ENGINES_MIRROR=...`。

**容器启动后 `/api/health` 返回 503（db: down）**

说明应用起来了但连不上数据库。检查：

```bash
docker compose -f docker-compose.prod.yml logs postgres | tail -30
docker compose -f docker-compose.prod.yml exec app node -e "console.log(process.env.DATABASE_URL)"
```

常见原因：密码含特殊字符未转义（`@`、`#` 需 URL 编码）、postgres 容器未 healthy 就启动了 app。

**登录收不到验证码**

`SMS_ADAPTER=mock` 时验证码不会真实发送，只写日志：

```bash
./deploy/deploy.sh logs app | grep -i "验证码\|code"
```

**页面 502 Bad Gateway**

Nginx 起来了但应用没起来：

```bash
docker compose -f docker-compose.prod.yml ps
./deploy/deploy.sh logs app | tail -50
```

**`bad interpreter: /bin/sh^M`**

脚本被 Windows 换行符污染。仓库已通过 `.gitattributes` 强制 `*.sh` 使用 LF；若手工拷贝文件，执行：

```bash
sed -i 's/\r$//' deploy/deploy.sh deploy/entrypoint.sh
```
