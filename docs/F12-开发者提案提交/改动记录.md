## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：开发方案第二个断点是「需求 ≠ 方案」，需要开发者把痛点转成可执行规格与报价，避免按一句话直接开发。
- 改动内容：
  - 新增 `src/domain/proposal/service.ts`：`submit()` / `listByNeed()` / `listMine()`。
  - 校验：BUILDER 角色 + 实名 + 需求 BIDDING + 理解 30-2000 字 + 规格 50-10000 字 + 工期 1-365 天 + 报价 >0 且 ≤ 托管额。
  - 数据库：`Proposal` 增加 `@@unique([needId, builderId])`。
  - API：`GET/POST /api/needs/[id]/proposals`。
  - UI：`ProposalForm`、需求详情方案列表（可展开查看理解/规格/案例）、`/console/proposals` 我的提案。
  - `NeedQueryService.detail` 的 viewer 增加 `isBuilder`，用于前端判断是否展示提案表单。
- 影响范围：
  - 竞标开始前提案列表为空（不泄露）。
  - 需求详情在 BIDDING 状态展示方案区。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：100 用例全绿（提案 11 例）
  - `npm run build`：EXIT=0（最终全量构建 41 条路由全部生成）
