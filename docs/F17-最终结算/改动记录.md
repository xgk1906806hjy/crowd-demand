## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：PRD 5.6 要求「验收达标后放款、未达标退款」；报价往往低于托管总额，差额必须退回支持者。
- 改动内容：
  - 新增 `settleProjectInTx()`：全部节点 RELEASED 时触发。
  - 差额 `leftover = totalAmount − quote`，按承诺金额比例分配，`floor` 取整、最后一笔承接余数。
  - 退款流水 `ESCROW → BACKER`，幂等键 `settle:{pledgeId}`，写 `PaymentOrder(REFUND)`。
  - 承诺置 `RELEASED`（已使用），项目 `COMPLETED`，需求 `ACCEPTING → COMPLETED` + 状态日志。
  - 报价等于托管额时跳过退款分支，仅置承诺状态。
- 影响范围：
  - 结算后托管账户余额应为 0（放款 + 退款 = 托管总额）。
  - 支持者可在我「我的承诺」看到终态。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：111 用例全绿（结算 2 例：12000/8000 退款、无差额无退款）
  - `npm run build`：EXIT=0（最终全量构建 41 条路由全部生成）

### v0.2 — 2026-11-23 — Bug 修复

- 背景：结算退款的 `PaymentOrder` 硬编码 `gateway: "mock"`，且外部未真正发起退款；需求 COMPLETED 通过裸 update 写入。
- 改动内容：
  - 最后一个节点验收时，按承诺份额以 `settle:{pledgeId}` 调用 `PaymentGateway.refund`，回执随事务传入。
  - `settleProjectInTx` 用回执写 `PaymentOrder(REFUND)`，`gateway` 取注入 provider。
  - 需求 `ACCEPTING → COMPLETED` 改走 `transitionNeedInTx`。
  - 记录已知限制：外部退款与事务之间存在极窄并发窗口，接持牌机构后改异步对账。
- 验证方式：结算 2 例（12000/8000 退款、无差额无退款）保持全绿，订单 provider 断言为 mock。
