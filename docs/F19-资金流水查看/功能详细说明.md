## 1. 功能目标

让运营方能随时核对「托管账户里还有多少钱、进来多少、放出去多少、退回去多少」，并对每一笔流水追溯到业务单据，支撑对账与风险发现。

## 2. 用户故事

- 作为运营方，我想看到托管余额与累计承诺/放款/退款，以便判断资金是否平衡。
- 作为运营方，我想逐笔查看流水（账户、方向、金额、余额快照、业务单号），以便对账。
- 边界场景：
  1. 非运营方访问 → 403 / 重定向。
  2. 数据量大 → 仅取最近 100 条展示，汇总按当前窗口计算（MVP 限制）。

## 3. 详细需求

### 3.1 输入

无参数（默认最近 100 条）。

### 3.2 输出

`{ escrowBalance, totalPledged, totalReleased, totalRefunded, entries[] }`，金额为「分」字符串。

### 3.3 业务规则

1. **余额由流水推导**：`escrowBalance = ΣCREDIT − ΣDEBIT`，不存在余额字段。
2. **汇总口径**：仅统计托管账户（ESCROW）的 PLEDGE 流入、RELEASE 流出、REFUND 流出。
3. **只读**：后台不提供任何修改流水的入口。
4. **权限**：仅 OPERATOR。

### 3.4 状态流转

无。

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 运营方 | 查看余额、汇总、流水明细 |
| 其他用户 | 无 |

## 4. 技术实现

- 涉及模块：`src/domain/ledger/query.ts`、`src/app/api/admin/ledger/route.ts`、`src/app/admin/ledger/page.tsx`
- 复用：`balanceOf`（F10）
- 已知限制：MVP 读取全部流水计算余额，数据量大后改为账户余额表 + 定期快照

## 6. 测试要点

1. 托管余额 = 承诺 − 放款 − 退款。
2. 汇总只统计 ESCROW 账户。
3. 非运营方访问被拒绝。
4. 流水方向与颜色标识正确（流入绿/流出红）。
