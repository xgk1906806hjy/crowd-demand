## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：开发方案 5.1 要求状态机集中管理，禁止 UI 层判断状态；每次流转必须可追溯。M2 阶段 B 的核心机制。
- 改动内容：
  - 新增 `src/domain/need/state-machine.ts`：`NEED_TRANSITIONS`（9 状态全量流转表）、`canTransition`、`isTerminal`、`isPubliclyVisible`、`isVotable`、`isPledgeable`、`ACTIVE_STATUSES`、中文标签与配色。
  - `src/domain/need/service.ts` 新增 `transition()`：发起者仅可 `DRAFT→COLLECTING`、`COLLECTING→FAILED`；运营方可执行任意合法流转；非法流转返回 `INVALID_STATE`。
  - 新增 API `POST /api/needs/[id]/status`。
  - 新增客户端组件 `NeedActions`（发布 / 撤销，撤销二次确认）。
- 影响范围：
  - 所有状态变更必须经 `transition()`，业务更新与 `NeedStatusLog` 同事务提交。
  - `DRAFT→COLLECTING` 时自动补 `publishedAt`。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：70 用例全绿（状态机 7 例 + 流转 6 例）
  - `npm run build`：EXIT=0

### v0.2 — 2026-11-23 — 重构

- 背景：AGENTS 第 2.3 条要求状态机集中在 domain 层，但承诺/投票/里程碑/结算/到期结算各自 `updateMany({ status })`，规则分散。
- 改动内容：
  - 新增 `src/domain/need/transition.ts`：`transitionNeedInTx()` 统一做「状态机校验 + 条件更新 + 写状态日志」，返回是否抢到流转权。
  - F07 票数达标、F09 承诺达标、F14 节点提交、F15 验收、F17 结算全部改走该入口。
  - `NeedService.transition()` 流转到 `FAILED` 时改调 `failNeedAndRefund`：全额退款完成后收口到 `REFUNDED`。
- 影响范围：非法流转从「静默不生效」变为显式抛错（调用方已先做业务校验，不改变对外行为）。
- 验证方式：`npx vitest run` 125 例全绿（状态机 7 例、流转 13 例、生命周期 7 例）。
