## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：PRD 5.4 要求「发起者选定方案后进入开发」，且资金已锁定，需要生成唯一的执行项目。
- 改动内容：
  - `ProposalService.select()`：权限校验（发起者/运营方）→ 需求 BIDDING → 提案归属与状态校验 → 事务内五步操作。
  - 事务：选中提案、驳回其余 SUBMITTED、条件更新需求为 IN_PROGRESS、写状态日志、创建 Project。
  - 并发：`updateMany({ where: { id, status: BIDDING } })`，count≠1 抛 `SelectionConflict` 回滚。
  - 数据库：`Project.needId` 增加 `@unique`，保证一需求一项目。
  - API：`POST /api/needs/[id]/select-proposal`；UI：`SelectProposalButton`（二次确认）。
- 影响范围：
  - 选标后需求离开竞标，不再接受新提案。
  - 项目 `totalAmount = pledgedAmount`，`releasedAmount = 0`，供 F16 释放。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：100 用例全绿（选标 4 例）
  - `npm run build`：EXIT=0（最终全量构建 41 条路由全部生成）
