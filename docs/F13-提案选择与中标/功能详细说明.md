## 1. 功能目标

由需求发起者（或运营方）在竞标方案中选定一个，形成唯一的中标项目：资金从「锁定」转为「待按里程碑释放」，需求进入开发阶段，其余提案自动驳回。

## 2. 用户故事

- 作为发起者，我想比较几份方案后选定一个，以便项目开始开发。
- 作为开发者，我想知道自己是否中标，以便安排工期。
- 边界场景：
  1. 该需求已选过标 → 拒绝，不产生第二个项目。
  2. 并发两次选标 → 条件更新只成功一次，另一次提示刷新。
  3. 非发起者尝试选标 → 拒绝。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| needId | path | 是 | 状态必须 BIDDING |
| proposalId | string | 是 | 属于该需求且状态 SUBMITTED |

### 3.2 输出

`{ projectId, proposalId, totalAmount }`（totalAmount = 需求已托管总额）

### 3.3 业务规则

1. **权限**：需求发起者或 `OPERATOR`。
2. **唯一项目**：`Project.needId @unique`，一个需求只能有一个中标项目。
3. **原子选标**：同一事务内完成「选中提案 → 驳回其余 → 需求转开发中 → 写状态日志 → 建项目」。
4. **并发保护**：`updateMany({ where: { id, status: BIDDING } })`，count≠1 则回滚。
5. **项目金额**：`totalAmount = Need.pledgedAmount`，`releasedAmount = 0`。
6. **审计**：写 `AuditLog`（PROPOSAL）。

### 3.4 状态流转

```
需求：BIDDING ──选定方案──→ IN_PROGRESS
提案：SUBMITTED ──被选中──→ SELECTED
      SUBMITTED ──未选中──→ REJECTED
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 需求发起者 | 选标 |
| 开发者 | 查看结果 |
| 其他用户 | 只读 |
| 运营方 | 可代为选标 |

## 4. 技术实现

- 涉及模块：`src/domain/proposal/service.ts`（`select`）、`src/app/api/needs/[id]/select-proposal/route.ts`、`src/components/need/select-proposal-button.tsx`
- 数据库变更：`Project.needId` 增加 `@unique`
- 事务：五步操作同一事务，`SelectionConflict` 触发回滚
- 资金：不直接划转，仅创建项目并保留托管余额，供 F16 按里程碑释放

## 5. 验收标准

- [x] 核心流程可用：选标 → 项目生成 → 需求开发中
- [x] 异常场景有明确提示：越权、重复选标、提案不存在
- [x] 单元测试通过：`tests/unit/proposal-service.test.ts`（选标 4 例）
- [x] 其余提案自动驳回、状态日志与审计齐全
- [ ] 选标后通知开发者（站内信/短信，后续）

## 6. 测试要点

1. 非发起者选标被拒绝。
2. 选标成功：需求 IN_PROGRESS、项目 1 个、其他提案 REJECTED、日志 1 条。
3. 重复选标返回 INVALID_STATE。
4. 提案不属于该需求返回 NOT_FOUND。
5. 项目金额等于托管总额。
