## 1. 功能目标

由需求发起者（或运营方）在竞标方案中选定一个，形成唯一的中标项目：资金从「锁定」转为「待按里程碑释放」，需求进入开发阶段，其余提案自动驳回。

选定之前，**付过订金的支持者可用「承诺选票」对提案投票**（PRD 5.4）：票权等于其在该需求的有效承诺金额，票数供发起者参考，最终决定权仍在发起者。

## 2. 用户故事

- 作为发起者，我想比较几份方案后选定一个，以便项目开始开发。
- 作为付过订金的支持者，我想把票投给我认可的方案，以便影响发起者的选择。
- 作为开发者，我想知道自己是否中标，以便安排工期。
- 边界场景：
  1. 该需求已选过标 → 拒绝，不产生第二个项目。
  2. 并发两次选标 → 条件更新只成功一次，另一次提示刷新。
  3. 非发起者尝试选标 → 拒绝。
  4. 未付订金的用户投提案票 → 拒绝（FORBIDDEN）。
  5. 支持者改投另一提案 → 旧票自动撤销，一个需求始终只有一票。
  6. 并发重复投同一提案 → 唯一约束兜底，幂等成功不产生第二票。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| needId | path | 是 | 状态必须 BIDDING |
| proposalId | string | 是 | 属于该需求且状态 SUBMITTED |

### 3.2 输出

`{ projectId, proposalId, totalAmount }`（totalAmount = 需求已托管总额）

### 3.3 业务规则

1. **权限**：需求发起者或 `OPERATOR`。
2. **唯一项目**：`Project.needId @unique`，一个需求只能有一个中标项目。
3. **原子选标**：同一事务内完成「选中提案 → 驳回其余 → 需求转开发中（`transitionNeedInTx`）→ 建项目」。
4. **并发保护**：状态机入口条件更新，count≠1 则回滚。
5. **项目金额**：`totalAmount = Need.pledgedAmount`，`releasedAmount = 0`。
6. **审计**：写 `AuditLog`（PROPOSAL / VOTE）。
7. **承诺选票**：仅竞标中、且对该需求有 `FROZEN/LOCKED` 承诺的用户可投；票权 = 有效承诺金额合计（分）。
8. **一人一票**：`ProposalVote @@unique([proposalId, userId])` + 改票时先删本需求其他提案上的旧票（同事务）。
9. **参考不决定**：票数与票权在提案列表公开展示；发起者可选任何 `SUBMITTED` 提案，不受票数约束（MVP 决策权归发起者，避免票数被小额承诺操纵）。

### 3.4 状态流转

```
需求：BIDDING ──选定方案──→ IN_PROGRESS
提案：SUBMITTED ──被选中──→ SELECTED
      SUBMITTED ──未选中──→ REJECTED
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 需求发起者 | 选标（参考支持者票数） |
| 付过订金的支持者 | 对提案投票 / 改票（一人一票，按承诺金额加权） |
| 开发者 | 查看结果 |
| 其他用户 | 只读 |
| 运营方 | 可代为选标 |

## 4. 技术实现

- 涉及模块：`src/domain/proposal/service.ts`（`select`、`voteForProposal`、`viewerSelection`、`listByNeed` 票数聚合）、`src/app/api/needs/[id]/select-proposal/route.ts`、`src/app/api/needs/[id]/proposal-vote/route.ts`、`src/components/need/select-proposal-button.tsx`、`src/components/need/proposal-vote-button.tsx`
- 数据库变更：无新增表（复用初始 schema 的 `ProposalVote`，含 weight 与 `(proposalId,userId)` 唯一约束）
- 事务：选标五步同一事务；改票的「删旧票 + 写新票」同一事务
- 资金：不直接划转，仅创建项目并保留托管余额，供 F16 按里程碑释放

- [x] 支持者承诺选票：加权、一人一票、可改票、幂等
- [x] 提案列表公开票数与票权，详情页支持投票/改票

- [ ] 票数自动决定中标（MVP 有意不做：决定权归发起者，防小额操纵；如需求变更再评估）

## 6. 测试要点

1. 非发起者选标被拒绝。
2. 选标成功：需求 IN_PROGRESS、项目 1 个、其他提案 REJECTED、日志 1 条。
3. 重复选标返回 INVALID_STATE。
4. 提案不属于该需求返回 NOT_FOUND。
5. 项目金额等于托管总额。
6. 未付订金投票被拒绝，且不落票。
7. 票权等于多笔有效承诺合计。
8. 重复投票幂等；改票撤旧票后仍只有一票。
9. 非竞标期 / 提案不属于该需求时投票被拒绝。
10. 列表票数与票权聚合正确；viewerSelection 返回已投提案与票权。
