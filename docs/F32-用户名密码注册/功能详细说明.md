## 1. 功能目标

让用户不依赖手机号短信或邮箱验证码即可完成注册：填写用户名 + 密码直接创建账号并自动登录。手机号/邮箱降级为可选绑定项，验证码登录保留为并列入口。

## 2. 用户故事

- 作为新用户，我想要只用用户名和密码注册，以便在没有可用手机号/邮箱（或验证码通道未接入）时也能立即使用平台。
- 作为已注册用户，我想要用用户名 + 密码登录，以便不必记住绑定的手机号/邮箱。
- 边界场景：
  - 用户名已被占用（含大小写变体）→ 明确提示冲突，不创建账号。
  - 同一 IP 短时间批量注册 → 限流拒绝。
  - 用户名与手机号/邮箱格式混淆（如纯数字）→ 格式规则直接排除。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| username | string | 是 | 4-20 位；字母开头；仅字母/数字/下划线；统一转小写存储与比对；禁用保留词（admin/root/system/support/official/administrator/service/help） |
| password | string | 是 | 固定 8 位；数字开头；必须含大写字母、小写字母、英文特殊符号；仅可打印 ASCII（复用 F31 强度规则，2026-11-23 变更） |
| confirmPassword | string | 前端必填 | 与 password 一致（仅前端校验） |

### 3.2 输出

- 注册成功：创建用户（roles=[BACKER]、kycStatus=NONE、nickname 默认取用户名），**直接签发会话**（与登录相同的 HttpOnly Cookie），返回用户信息（含 username）。
- 失败：统一 Result 错误结构；用户名占用返回 CONFLICT(409)，格式/强度错误 VALIDATION(400)，限流 RATE_LIMITED(429)。

### 3.3 业务规则

1. 用户名全局唯一，**大小写不敏感**（存储与查询均小写），防止大小写变体冒充。
2. 用户名不得为纯数字或含 `@`，与手机号/邮箱标识空间天然隔离；密码登录按「手机号格式 → 邮箱格式 → 用户名」顺序识别账号类型。
3. 注册即登录：成功后立即签发 JWT 会话，无需二次登录。
4. 防批量注册：同一 IP 每小时最多注册 5 个账号（进程内滑动窗口；取不到 IP 时不限流，依赖反代透传 X-Forwarded-For）。
5. 密码 scrypt 哈希存储（复用 F31），禁止明文；注册不产生任何资金操作。
6. 用户名账号同样适用 F31 密码失败锁定（5 次锁 15 分钟）与防枚举统一文案。
7. 手机号/邮箱可后续在「安全设置」绑定（邮箱走 F31 BIND 验证码）；绑定冲突规则不变。
8. 涉及资金的操作仍强制实名认证（F02），免验证码注册不放松任何资金护栏。
9. 注册/登录写审计日志（REGISTER_SUCCESS / LOGIN_SUCCESS）。

### 3.4 状态流转

不涉及业务状态机（用户创建即终态；KYC 状态流转归 F02）。

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 游客 | 注册（无需登录态） |
| 已登录用户 | 不可重复注册（前端入口隐藏；接口本身无登录态要求，重复提交只会创建新账号，与验证码注册行为一致） |
| 运营方 | 无特殊权限（本功能） |

## 4. 技术实现

- 涉及模块：
  - `src/domain/auth/service.ts` —— `AuthService.register()`；`passwordLogin` 账号识别扩展用户名；`toLoginUser` 增加 username
  - `src/domain/auth/username.ts` —— 用户名格式/保留词校验与归一化（独立纯函数，便于单测）
  - `src/app/api/auth/register/route.ts` —— 注册接口（签发会话 Cookie）
  - `src/app/api/auth/password/login/route.ts` —— 文案放宽为「用户名/手机号/邮箱」
  - `src/app/api/auth/me/route.ts` —— 返回 username
  - `src/app/(public)/login/page.tsx` —— 新增「注册」Tab；密码登录账号输入提示更新
- 数据库变更：`User.username String? @unique`（增量 SQL：`prisma/patches/2026-11-23-f32-username.sql`）。
- 外部依赖：无（不触碰短信/邮件/支付适配器）。
- 资金操作：无。

- [x] 既有手机号/邮箱验证码登录与密码登录行为不变
- [x] 单元测试通过
- [ ] Playwright E2E 通过（主流程，暂欠，与 F01/F31 同批补）

## 6. 测试要点

- 注册成功：用户落库字段（username 小写、passwordHash 非空、roles、nickname 默认值）、会话签发。
- 用户名规则：长度边界（3/4/20/21）、首字符数字、非法字符、中文、保留词、大小写冲突。
- 密码强度：复用 F31 规则边界。
- 限流：同 IP 5 次成功 + 第 6 次拒绝；窗口过期后恢复；不同 IP 互不影响。
- 用户名密码登录：成功/错误密码/锁定/防枚举文案与手机号账号一致。
- 回归：手机号/邮箱验证码登录、手机号/邮箱密码登录不受影响。

## 7. 关联功能

- 上游：F01（会话与验证码体系）、F31（密码哈希/锁定/防枚举）。
- 下游：F02 实名认证（资金前置）、F31 邮箱绑定（可选补充标识）。

## 8. 风险与合规说明

- 免验证码注册无法保证账号背后是真实自然人，批量注册/羊毛风险上升；当前以 IP 限流 + 资金操作强制实名兜底。
- 面向公众正式运营时，国内监管对互联网信息服务有真实身份信息（手机号）要求；届时应恢复验证码注册为主路径或接入一键登录，本功能保留为内部/演示与低门槛入口。该决策已在 PRD v0.4 变更说明中记录。
