## 1. 功能目标

让真实用户在平台上把"我哪里痛"写清楚并公开发布，形成后续投票、付费承诺、开发者竞标的入口。发布质量直接决定后面能否被报价，因此在发布环节强制结构化和最低信息量。

## 2. 用户故事

- 作为完成实名的普通用户，我想把一个具体的生活/工作痛点发布成需求，以便让有同样痛点的人投票、让开发者评估能否实现。
- 作为发起者，我想保存草稿而不公开，以便先想清楚再发布。
- 边界场景：
  1. 未实名用户点发布 → 明确提示先去实名，不落库。
  2. 描述只有一句话「想要个记账工具」→ 拒绝，提示至少 30 字并说明要写现状/场景/期望。
  3. 目标金额填 `1e3` 或 `-100` → 金额格式校验失败，不进入领域层。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| title | string | 是 | 5-60 字符（按 Unicode 字符计） |
| description | string | 是 | 30-5000 字符，写清痛点/场景/期望 |
| targetAudience | string | 否 | ≤ 100 字符 |
| expectedForm | string | 否 | ≤ 100 字符 |
| attachments | string[] | 否 | 最多 9 个，元素为非空字符串（OSS key） |
| targetAmountYuan | string/number | 是 | 元，最多两位小数；范围 100-1,000,000 元 |
| voteThreshold | number | 否 | 1-10000 整数，默认 100 |
| deadline | ISO string | 否 | 必须晚于当前时间，且不超过 365 天 |
| publish | boolean | 否 | 默认 true；false 表示保存草稿 |

### 3.2 输出

- `POST /api/needs` 返回 `{ id, status, publishedAt }`，前端跳转 `/needs/{id}`。
- 控制台「我的需求」返回列表：标题、状态、票数/门槛、已承诺/目标金额。

### 3.3 业务规则

1. **实名门槛**：仅 `kycStatus = VERIFIED` 可发布（F04 依赖 F02），防止垃圾需求与虚假承诺。
2. **发布即授予角色**：首次发布自动把 `REQUESTER` 追加到用户角色，幂等不重复。
3. **金额只存整数分**：接口层用 `yuanToCents` 转换，领域层校验区间，禁止浮点。
4. **发布与草稿分离**：草稿 `DRAFT` 不对外可见，发布后 `COLLECTING` 并写 `publishedAt`。
5. **状态日志必写**：创建时写入初始 `NeedStatusLog`（发布：DRAFT→COLLECTING；草稿：null→DRAFT）。
6. **审计**：每次发布写 `AuditLog`（action=NEED）。

### 3.4 状态流转

```
（创建）→ DRAFT（草稿，仅发起者可见）
DRAFT ──发布──→ COLLECTING（征集中，公开可投票）
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 不可发布 |
| 已登录未实名 | 不可发布（返回 FORBIDDEN） |
| 已实名用户 | 创建草稿 / 发布需求 |
| 运营方 | 同已实名用户 + 后续任意合法流转（F06） |

## 4. 技术实现

- 涉及模块：`src/domain/need/service.ts`（`create`）、`src/app/api/needs/route.ts`（POST）、`src/app/(console)/console/needs/new/page.tsx`
- 数据库变更：`Need` 增加 `voteCount`、`pledgedAmount` 冗余字段（榜单排序用）
- 外部依赖：无（附件仅存 OSS key，上传能力在 M3 F25 实现）
- 资金操作：本功能只记录目标金额，不产生任何资金流水

## 5. 验收标准

- [x] 核心流程可用：实名用户可发布并在广场看到
- [x] 异常场景有明确提示：未实名、标题/描述过短、金额越界、截止时间非法
- [x] 单元测试通过：`tests/unit/need-service.test.ts` 7 例
- [x] 发布后状态日志与审计日志齐全
- [ ] Playwright E2E（主流程 E2E 在 F09 后统一补）

## 6. 测试要点

1. 未实名发布被拒绝且不落库。
2. 标题/描述边界值：4/5/60/61 字符，29/30 字符。
3. 金额边界：99.99 / 100 / 1,000,000 / 1,000,000.01。
4. 截止时间：过去时间、366 天后均拒绝。
5. 草稿与发布两条路径的 `status`、`publishedAt`、状态日志差异。
6. 重复发布不重复授予 REQUESTER 角色。
