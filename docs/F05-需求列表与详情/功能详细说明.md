## 1. 功能目标

把发布出来的需求组织成可浏览、可检索、可分页的公开广场，并给出单条需求的完整信息（痛点、金额、进度、生命周期），让支持者判断是否投票、让开发者判断是否竞标。

## 2. 用户故事

- 作为路人，我想按热度/承诺金额浏览需求，以便找到我愿意支持的那一个。
- 作为支持者，我想看到某条需求的票数、目标金额、已承诺进度和状态变化，以便判断它是否靠谱。
- 边界场景：
  1. 访问不存在的 id → 404。
  2. 访问他人草稿 → 按 404 处理，不泄露内容。
  3. 数据库不可用 → 页面降级提示，不白屏。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| sort | hot/pledge/latest/deadline | 否 | 非法值回退 hot |
| status | ALL / NeedStatus | 否 | 非法值返回 VALIDATION |
| keyword | string | 否 | ≤ 50 字符，匹配标题或描述（不区分大小写） |
| page | number | 否 | ≥ 1，默认 1 |
| pageSize | number | 否 | 1-50，默认 12 |

### 3.2 输出

- 列表项：`id/title/summary/status/statusLabel/voteCount/voteThreshold/targetAmount/pledgedAmount/progress/deadline/publishedAt/requesterName`
- 详情额外返回：`description/targetAudience/expectedForm/attachments/createdAt/requesterId/statusLogs（最近 20 条）/viewer{loggedIn,isRequester,kycVerified,hasVoted,canVote}`
- 金额字段一律为「分」的字符串，避免 JSON 无法序列化 bigint。

### 3.3 业务规则

1. **草稿不公开**：列表永远排除 `DRAFT`；详情仅发起者可见。
2. **列表默认口径**：`status=ALL` 时展示除草稿外全部状态；支持按单状态筛选。
3. **摘要生成**：描述压平空白后截取 110 字，超出加省略号。
4. **进度计算**：`pledgedAmount / targetAmount × 100`，保留 1 位小数，目标为 0 时返回 0。
5. **昵称兜底**：未设置昵称显示「匿名用户」，绝不展示手机号。
6. **排序下沉**：排序规则集中在 `buildNeedOrderBy`，页面不拼 `orderBy`。

### 3.4 状态流转

本功能只读展示，不触发流转；状态变更见 F06。

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 浏览公开列表与公开详情 |
| 已登录 | 同上 + 可见自己的草稿 |
| 发起者 | 查看自己草稿的完整内容与生命周期 |
| 运营方 | 浏览全部（草稿需按 id 直接访问） |

- 涉及模块：`src/domain/need/query.ts`、`src/app/api/needs/route.ts`(GET)、`src/app/api/needs/[id]/route.ts`、`src/app/(public)/needs/page.tsx`、`src/app/(public)/needs/[id]/page.tsx`

- 外部依赖：无

## 6. 测试要点

1. 草稿不出现在列表；他人草稿详情返回 NOT_FOUND。
2. 四种排序的 orderBy 首项正确，且都有稳定次级排序。
3. 关键词命中标题与描述，超长关键词被拒绝。
4. 进度计算：0%、50%、33.3%、超额 200%、目标为 0。
5. 分页边界：page=0 归一到 1，pageSize>50 截断为 50。
