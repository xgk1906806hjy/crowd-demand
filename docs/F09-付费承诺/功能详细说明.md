## 1. 功能目标

把「点赞式支持」升级为「真金白银的预购承诺」，用付费意愿过滤伪需求：只有愿意先付订金的人，才计入需求能否启动的判定。这是整个平台最核心的信号机制。

## 2. 用户故事

- 作为已实名用户，我想为某个需求预付订金，以便推动它进入开发。
- 作为发起者，我想看到已承诺金额与进度条，以便判断还差多少能达到目标。
- 边界场景：
  1. 未实名用户点预付 → 拒绝并引导实名。
  2. 网络抖动重复提交同一笔 → 幂等键命中，不重复扣款。
  3. 需求已过承诺截止时间 → 拒绝，提示已截止。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| needId | path | 是 | 存在且状态为 PLEDGING |
| amountYuan | string/number | 是 | 元，最多两位小数，转整数分 |
| idempotencyKey | string | 否 | ≤100 字符；不传则服务端生成 |

### 3.2 输出

`{ pledgeId, pledgedAmount, targetAmount, progress, needStatus, funded }`

### 3.3 业务规则

1. **实名门槛**：仅 `kycStatus = VERIFIED` 可承诺。
2. **状态门槛**：仅 `PLEDGING`（票数达标后）可承诺；`COLLECTING` 需先投票。
3. **截止门槛**：`deadline` 已过则拒绝。
4. **金额约束**：单笔 ≥ 10 元；单笔 ≤ `MAX_PLEDGE_AMOUNT_CENTS`（默认 5 万元）；同一用户同一需求累计 ≤ `MAX_USER_PLEDGE_CENTS`（默认 20 万元）。
5. **资金流向**：支持者账户 →（DEBIT）托管账户（CREDIT），复式记账，一借一贷。
6. **幂等**：`Pledge.idempotencyKey` 唯一；重复提交返回既有结果，不重复冻结。
7. **事务**：承诺记录、账本分录、需求金额自增、支付单、状态流转在同一事务内提交。
8. **审计**：每次承诺写 `AuditLog`（action=PLEDGE）。

### 3.4 状态流转

承诺不改变需求状态，除非本次承诺使总额达到目标（见 F11）：

```
PLEDGING ──累计承诺 ≥ 目标金额──→ BIDDING（系统自动，同时锁定全部承诺）
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 仅浏览进度 |
| 已登录未实名 | 不可承诺 |
| 已实名用户 | 承诺、查看自己的承诺 |
| 发起者 | 不可对自己需求承诺（后续 F23 增加限制） |
| 运营方 | 可查看全部承诺与流水 |

- 涉及模块：`src/domain/pledge/service.ts`、`src/domain/ledger/service.ts`、`src/infrastructure/payment/gateway.ts`、`src/app/api/needs/[id]/pledges/route.ts`、`src/app/api/pledges/mine/route.ts`、`src/components/need/pledge-form.tsx`、`src/app/(console)/console/pledges/page.tsx`

- ⚠️ 资金操作：全部走账本 + 事务 + 幂等键；金额一律整数分

## 6. 测试要点

1. 未实名/非承诺期/已截止三类拒绝。
2. 金额边界：5 元、10 元、单笔上限、单笔上限+1 分。
3. 幂等：同键重复提交承诺数、分录数、需求金额均不变。
4. 达标：承诺后需求转 BIDDING，承诺置 LOCKED，状态日志 1 条。
5. 账本：借贷金额相等、托管余额 = 承诺总额、余额快照正确。
6. 公开列表不返回手机号。
