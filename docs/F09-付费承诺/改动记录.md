## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：开发方案把「票 ≠ 钱」列为第一断点，付费承诺是平台的核心信号。PRD 5.3 要求承诺款进入托管、未达标全额退回。
- 改动内容：
  - 新增 `src/infrastructure/payment/gateway.ts`：`PaymentGateway` 接口 + `MockPaymentGateway`（freeze/release/refund），生产环境使用 Mock 直接抛错。
  - 新增 `src/domain/pledge/service.ts`：`PledgeService.pledge()` / `listByNeed()` / `listMine()`。
  - 校验链：实名 → 需求状态 `PLEDGING` → 截止时间 → 单笔 10 元-5 万元 → 单人累计 20 万元。
  - 幂等：`Pledge.idempotencyKey` 唯一，重复提交返回既有结果。
  - 事务：承诺记录、账本双分录、`Need.pledgedAmount` 自增、`PaymentOrder`、达标流转同事务。
  - API：`POST/GET /api/needs/[id]/pledges`、`GET /api/pledges/mine`。
  - UI：`PledgeForm`（9.9/49/99/199 档位 + 自定义）、需求详情「最近支持」列表、`/console/pledges` 我的承诺。
- 影响范围：
  - 需求详情页在 `PLEDGING` 状态展示预付表单；未登录/未实名分别引导登录与实名。
  - 承诺成功后进度条与金额即时刷新。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：89 用例全绿（承诺 9 例）
  - `npm run build`：EXIT=0，26 条路由全部生成（含 6 个新 API 与 1 个新页面）

### v0.2 — 2026-11-23 — 重构

- 背景：随 F06 收敛状态流转入口；F10 账本新增锁与余额护栏后需确认承诺路径行为不变。
- 改动内容：`PledgeService.pledge()` 的 `PLEDGING → BIDDING` 改走 `transitionNeedInTx`；承诺入账 `BACKER → ESCROW` 不受托管余额护栏影响（出账方是支持者账户）。
- 验证方式：`npx vitest run` 承诺 9 例全绿（含达标注置 LOCKED）。
