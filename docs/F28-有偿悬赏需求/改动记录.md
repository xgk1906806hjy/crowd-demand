## 详细记录

### v0.1 — 2026-11-23 — 新建

- 背景：PRD v0.1 把众筹写成唯一路径，导致"需求方自己出钱找人做"无法发布。PRD v0.2 修正为多模式，本功能承接其中的「有偿悬赏」路径。
- 改动内容：
  - 新增 `NeedMode`（`OPEN` / `BOUNTY` / `CROWDFUND`），`Need` 增 `mode`、`bountyAmount`、`bountyDeadline`。
  - 新增 `BountyEscrow` 表，独立记录悬赏托管与已退还金额，与 `Pledge` 分离，避免两种资金口径混算。
  - 状态机 `canTransition` 改为 mode 感知：仅悬赏/认领允许 `DRAFT → BIDDING`。
  - 选标在悬赏/认领模式下由需求方本人决定，不叠加承诺票权。
  - 退余款走独立幂等键 `bountyrefund:{needId}`，与众筹的 `settle:{pledgeId}` 分离。
- 影响范围：需求发布、状态机、选标、结算；众筹路径行为不变。
- 验证方式：单元测试覆盖发布分流/幂等/退款/越权/部分结算；`npx tsc --noEmit`；`npm run build`；真实实例冒烟。

### v0.2 — 2026-11-23 — 优化（服务端落地 + 前端改造）

- 背景：v0.1 只登记了规则，代码仍把众筹当唯一路径；检查中发现悬赏需求根本无法提交方案——提案报价校验硬编码为 `quote <= pledgedAmount`，而悬赏没有 Pledge，`pledgedAmount` 恒为 0。
- 改动内容：
  - 报价上限改为按模式取：悬赏 = `bountyAmount`，众筹 = `pledgedAmount`，无偿 = 0；无偿需求只接受 0 报价。错误文案同步区分。
  - 需求查询视图（列表 / 详情 / 我的需求）补充 `mode`、`modeLabel`、`bountyAmount`、`bountyDeadline`，供前端分流展示。
  - 发布页 `console/needs/new`：三张模式卡片（有偿悬赏 / 无偿求助 / 众筹），金额区按模式条件渲染；悬赏提交后立即预付托管，按钮文案变为「支付 ¥X 并发布」。
  - 详情页：头部加模式徽标；数据区按模式切换（悬赏显示悬赏金额/托管状态/方案数/征集截止，众筹保留票数与承诺进度）；投票按钮与承诺入口只在众筹出现；悬赏/认领的需求方可「撤回并退款」。
  - 列表页与我的需求：模式标签 + 悬赏金额，非众筹不再显示 0/0 的承诺进度。
  - 新增客户端组件 `bounty-cancel-button.tsx`，对接 `/api/needs/{id}/bounty-cancel`。
- 影响范围：需求列表、详情、发布、我的需求；众筹路径展示与行为保持一致。
- 验证方式：`npx vitest run` 18 文件 150 例全绿（新增 3 例报价上限用例）；`npx tsc --noEmit` exit 0；`npm run build` 成功，31 条路由（含 `bounty-cancel`）。
- 遗留：无偿模式下项目总金额为 0，里程碑计划表单尚未做零金额适配（F30 承接）。

### v0.3 — 2026-11-23 — Bug 修复（草稿态漏洞）

- 现象：悬赏需求若以「存草稿」方式创建（`publish=false`），详情页的发布按钮仍会流转到众筹的 `COLLECTING`，或绕过托管直接进入 `BIDDING`，导致**未付款却公开征集方案**。
- 根因：`REQUESTER_TRANSITIONS` 只登记了 `DRAFT → COLLECTING`，未按模式分支；状态流转未校验悬赏托管是否已成立。
- 修复：
  - 发起者白名单在非众筹模式下额外允许 `DRAFT → BIDDING`；众筹仍只允许 `DRAFT → COLLECTING`。
  - 悬赏 `DRAFT → BIDDING` 前强制校验 `BountyEscrow.status = HELD`，否则返回 `INVALID_STATE`（文案：需先支付悬赏金并完成托管）。
  - `NeedActions` 组件接收 `mode`，草稿发布时按模式提交到 `BIDDING` 或 `COLLECTING`。
- 验证：新增 3 例（未托管禁止征集、托管后可征集、悬赏不能进承诺期），单测 153 例全绿；`tsc` exit 0；生产构建 31 路由；服务器双冒烟（众筹 42 项 + 悬赏 33 项）全通过；账本借贷差额 0。
