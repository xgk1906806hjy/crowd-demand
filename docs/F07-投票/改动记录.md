## 详细记录

### v0.1 — 2026-11-21 — 新建

- 背景：PRD 5.2 要求登录用户一人一票；开发方案 5.3 明确 MVP 用「实名用户一人一票 + 数据库唯一约束」作为反刷票前置约束。
- 改动内容：
  - 新增 `src/domain/vote/service.ts`：`VoteService.cast()` / `cancel()`。
  - 三重闸门：实名校验、`(needId,userId)` 唯一约束、仅 `COLLECTING` 可投。
  - 事务内完成「写票 → `voteCount` 自增 → 达标条件更新 `COLLECTING→PLEDGING` → 写状态日志」。
  - 新增 API `POST /api/needs/[id]/vote`（`action: UP | CANCEL`）。
  - 新增客户端组件 `VoteButton`：未登录引导登录、未实名引导实名、已投可撤回、票数即时更新。
- 影响范围：
  - 票数冗余字段 `Need.voteCount` 与 `Vote` 表严格同步。
  - 达标后需求进入承诺期，投票关闭。
  - 每次投票/撤票写 `AuditLog`（action=VOTE）。
- 验证方式：
  - `npm run typecheck`：0 错误
  - `npm test`：70 用例全绿（投票 7 例）
  - `npm run build`：EXIT=0

### v0.2 — 2026-11-23 — 重构

- 背景：随 F06 收敛状态流转入口。
- 改动内容：`VoteService.cast()` 的 `COLLECTING → PLEDGING` 由内联 `updateMany + create log` 改为 `transitionNeedInTx`；并发语义不变（条件更新只成功一次）。
- 验证方式：`npx vitest run` 投票 7 例全绿。

### v0.3 — 2026-11-24 — 需求变更

- 背景：用户要求「每个需求每个人既可以投票也可以领取需求」。原实现投票需实名，且投票按钮只在众筹需求出现。
- 改动内容：
  - `VoteService.cast` 删除 `kycStatus === VERIFIED` 校验，登录即可投。
  - `isVotable` 扩展为 `COLLECTING || BIDDING`（竞标期票数仅表态，不触发流转）。
  - 需求详情页投票按钮对所有模式、所有非草稿状态渲染；`VoteButton` 删除「实名后可投票」分支与 `kycVerified` 入参。
- 影响范围：投票接口、需求详情页；达标自动流转仍只在 COLLECTING 发生。
- 验证方式：`tests/unit/vote-service.test.ts` 8 例（新增「未实名可投」「竞标期可投」）；全量 215 例通过；`npx tsc --noEmit`、`npm run build` 通过。
