## 1. 功能目标

用零成本的支持票表达「这个需求有多少人真的需要」，作为需求进入付费承诺期的第一道筛选门槛。投票本身不产生资金，但必须有足够成本（实名）来抑制刷票。

## 2. 用户故事

- 作为实名用户，我想对认同的需求投一票，以便让它更快达到门槛进入承诺期。
- 作为实名用户，我想撤回误投的票，以便表达真实意愿。
- 边界场景：
  1. 未实名用户点投票 → 拒绝并引导实名。
  2. 同一用户连点两次 → 幂等，票数仍为 1。
  3. 需求已进入承诺期 → 拒绝投票（票数已定档）。

## 3. 详细需求

### 3.1 输入

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| needId | path | 是 | 存在且非草稿 |
| action | UP / CANCEL | 否 | 默认 UP；其他值 400 |

### 3.2 输出

`{ voted, voteCount, voteThreshold, status, thresholdReached }`

### 3.3 业务规则

1. **实名门槛**：`kycStatus = VERIFIED` 才能投票（MVP 反刷票第一道闸）。
2. **一人一票**：数据库唯一约束 `(needId, userId)`，重复投票幂等返回当前票数。
3. **状态限制**：仅 `COLLECTING` 可投票；取消投票同样仅限征集期。
4. **票数冗余**：`Need.voteCount` 与 `Vote` 记录在同一事务内增减，保证榜单排序准确。
5. **达标自动流转**：票数 ≥ `voteThreshold` 时，条件更新 `COLLECTING→PLEDGING` 并写状态日志（原因含票数）。
6. **审计留痕**：投票/撤票均写 `AuditLog`（action=VOTE）。

### 3.4 状态流转

```
COLLECTING ──票数 ≥ 门槛──→ PLEDGING（系统自动，actor=null）
```

### 3.5 权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录 | 仅浏览，点位引导登录 |
| 已登录未实名 | 不可投票，引导实名 |
| 已实名用户 | 投票、撤回（征集期内） |
| 运营方 | 同已实名用户 |

## 4. 技术实现

- 涉及模块：`src/domain/vote/service.ts`、`src/app/api/needs/[id]/vote/route.ts`、`src/components/need/vote-button.tsx`
- 数据库变更：`Need.voteCount`（冗余票数）+ `@@index([status, voteCount])`
- 事务：`vote.create` + `need.update(increment)` + 条件流转 + `needStatusLog.create` 在同一交互式事务
- 并发：`updateMany({ where: { id, status: COLLECTING } })` 保证只流转一次
- 外部依赖：无

## 6. 测试要点

1. 未实名投票被拒绝，票数不变。
2. 同一用户重复投票票数仍为 1，`Vote` 只有一条。
3. 第二票达到门槛：状态变 PLEDGING、日志 1 条、`thresholdReached=true`。
4. 非征集期投票/撤票均返回 INVALID_STATE。
5. 撤票后票数回落，`voted=false`。
6. 未投票时撤票幂等。
